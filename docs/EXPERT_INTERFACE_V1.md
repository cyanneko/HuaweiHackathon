# 独立专家与逐回调选择器技术规范 v1.0

状态：团队协作契约；先交付、比较独立专家，再训练选择器。本文规定接口；[最小运行骨架](../expert_runtime/README.md)的实现子集与限制单列，不声明任意旧方法已自动兼容。日期：2026-10-28。

## 1. 目的和依据

各成员开发自己的数学规则、缓存策略或超小神经网络，通过相同接口产生合法动作。后期在同一个真实引擎状态上，由小决策树选一个专家执行。优先保留低开销且效果互补的少量专家，不能仅按独立总分最高者拼接后就认定融合有效。

本次重新读取[官方题面](https://www.chaspark.com/#/races/competitions/1326693349800046592)的[公开接口](https://www.chaspark.com/chasiwu/v1/content/races/question/detail/1326693349800046592)，响应 SHA-256 为 `75a53f1c786cff23a3a63c69492d51aa8595da719dcd08e6af500ef966a4a70f`，与此前 2026-10-26/27 核验件相同。服务器标注的更新时间为 2026-10-20，而非本文日期。本文的接口、配额和验收建议属于团队工程选择，不能冒称官方新增要求。

官方边界继续遵循 [Agent 指南](AGENT_GUIDE.md)；评分、版本和成员集合依 [公共评测器](../evaluation/README.md)。以后题面有变更须先核对并升级契约。

## 2. “每一步”的准确含义

决策点是官方 `onMemoryOverflow`、`onPartitionMiss`、`onPeriodicAdjust` 的一次调用。一条输入操作可能触发两个回调，很多操作没有回调；SWITCH 本身没有回调。下文的“测试案例”指一份输入文件及其完整操作流。不增加普通 hit/INSERT 的事件钩子，不修改 engine 来暴露隐藏信息。

允许：当前 SystemState、当前回调目标和 tuple_size、一个 next_op，以及由此前真实回调合法获得的自有历史。禁止：完整 op_lines、文件名/种子/元数据标签、未来操作、隐藏的真实 miss_penalty、N、B、完整操作序号。不能把离线训练可读的输入头参数接进在线专家。

官方提交仍是仅定义 `MySpillScheduler` 的一个 C++14 文件，无 main/engine；导出时把内部公共头、专家辅助类型和模型参数合并到该文件，不能依赖未提交的本地头文件。独立专家模块和最终选择器都由这个外壳转接官方三回调，不能让多个同名 MySpillScheduler 同时定义。

## 3. v1 内部接口

下面代码是规范中的类型/签名，不是已经发布的库；成员按同一布局适配。集成方将 `hj_expert_v1` 公共类型集中定义在一个带包含保护的共享头文件中，各专家包含该头文件，不各自重复定义这些类型。官方 `SystemState`、`Action`、`SpillScheduler` 原样使用，并在这些类型/签名之前可见。模型权重必须内嵌；不得依赖额外运行库。

```cpp
#include <cstdint>
#include <vector>

namespace hj_expert_v1 {
using ExpertId = std::uint16_t;
constexpr ExpertId kNoExpert = 65535;

enum class CallbackKind { Overflow, Miss, Periodic };

struct DecisionContext {
    const SystemState& state;   // 借用，不复制；仅本次调用有效
    CallbackKind kind;
    int op_id;                 // Periodic: -1
    int partition_id;          // Periodic: -1
    std::int64_t tuple_size;   // 仅 Overflow 有效，其余为 0
    std::uint64_t callback_index; // 每测试案例从 0 开始，三类回调统一递增
};

struct DispatchView {
    ExpertId selected_id;      // 回退后最终专家 ID
    const std::vector<Action>& actions; // 最终将返回引擎的完整动作
};
}

namespace member_method_v1 {  // 每个实现使用唯一 namespace
class Expert {
public:
    void reset();
    void observe(const hj_expert_v1::DecisionContext& ctx);
    void decide(const hj_expert_v1::DecisionContext& ctx,
                std::vector<Action>& out) const;
    void onDispatch(const hj_expert_v1::DecisionContext& ctx,
                    const hj_expert_v1::DispatchView& chosen);
};
}
```

各方法使用同样的 `Expert` 类接口，但在自己的 namespace 内。默认构造不读取输入/文件/环境变量；`reset()` 后等价于新的初始实例。固定模型参数可以共享只读存储。ExpertId 由集成清单稳定分配，不靠编译顺序；65535 保留为无专家，回退专家也需固定 ID。

`decide` 必须写入完整动作序列：本规范统一要求**专家在入口自行 `out.clear()`**，保留 capacity 可以，不能追加上次动作。空 periodic 动作是合法答案；overflow/miss 不得用空动作代替无法处理的情形。方法须支持正式输入范围，若有更窄范围，注册清单与选择器必须在调用前排除它，并选已验证的全范围专家。

每位成员同时交付独立官方适配文件 `standalone.cpp`：构造时为每个测试案例 reset，然后按下节顺序，以该方法的固定专家 ID 转发三回调。若仅支持较窄范围，独立版也须声明并注册同一个全范围回退专家，记录触发范围与次数，不能把含回退的表现称为纯专家表现。训练/历史参数及动作平局规则保持一致，避免独立版与集成版变成两个算法。

### 生命周期与状态归属

每个测试案例创建新外壳及专家实例并 reset，或复用实例时显式 reset 全部专家、历史、缓存和 callback_index；不能在每条输入操作或每次回调重置。注册专家集合在一个测试案例内固定，包含全范围回退专家。可以在首个真实回调、任何专家 observe 之前，依据合法可见且足以判断的案例范围整体排除不适用专家，之后不再临时移出/重新加入。一次回调的固定顺序是：

1. 用官方传入状态建立借用的 DecisionContext，分配当前 callback_index。
2. 所有已注册专家各执行一次 `observe(ctx)`；无状态专家为空实现。即使本次不满足某专家的 decide 支持范围，它也要同步真实回调；observe/onDispatch 均须接受三类回调，并对该注册集合可能收到的正式全范围状态安全。supported_ranges 较窄只限制 decide 选择，不能在 observe 中先用超范围索引访问固定数组，再指望门控排除。共同历史特征优先由共享组件一次计算，不要求所有专家重复扫描分区。
3. 计算选择器必要特征并选择一个已注册且支持当前状态的合法专家 ID。未注册 ID、`kNoExpert` 或不支持当前状态的选择走已声明的全范围回退专家。v1 未训练树时使用固定 ID；可以在 periodic 预先选定空操作专家，但必须在记录中声明。
4. 只对选中专家调用一次 `decide(ctx, out)`。不要为了选它而先运行全部专家。
5. 若启用运行时动作检查或回退，先完成检查，再得到最终专家 ID/动作。未通过的候选动作全部丢弃，不能拼接半份计划；回退不重做 observe，至多再调用一次已验证的全范围回退专家 decide，不循环尝试专家。回退专家自身无后备链；其计划失败须报告错误，不能无限递归回退。全量审计应另设诊断构建，生产检查开销必须计时；即使不启用生产动作检查，各专家仍须独立通过合法性验收，不能靠回退掩盖不合格方法。
6. 所有注册专家各接收一次 `onDispatch(ctx, final_view)`，包括空动作与未被选中的专家；这表示“动作已选定、即将返回”，不是已经执行。随后增加本地计数并返回动作。

`observe` 是**回调观测**，不是全输入事件观察。callback_index 不是操作步数，更不是每分区访问计数。相同内容的 next_op 既可能是同一输入的重复展示，也可能是两个真实重复输入；仅按内容去重无法恢复完整事件流。v1 默认只把 next_op 当本次即时特征，不累计为真实访问次数。若使用回调曝光频率，必须命名为 callback exposure、声明重复与选择偏差。

`decide` 是对当前真实状态的无策略副作用提案。`const` 还不够：禁止通过 mutable、全局变量、共享缓存修改影响未来策略的记忆、随机状态、ghost 或热度；允许只影响执行效率的 scratch/cache，但必须声明容量和初始化/命中成本，并证明清空它不改变动作。缓存不得跨输入污染。

`onDispatch` 可记最终动作意图，不能给未选专家记自己的假动作，不能增加虚构 hit/miss/收益或推断完整输入进度。下次 observe 以真实 state 为权威；中间普通输入的变化不等于这些动作的独立收益，不得当反事实奖励。想记录“已执行”时，必须有真实快照支持并保留不可辨识的边界。不能读取引擎内部状态或保存临时 state/actions 引用。

有状态专家处于**共同实际轨迹**：未选中时继续接收允许的观察和最终动作通知，但不在自己的虚拟内存世界运行。即使实现完全遵守接口，切换后的表现也不等于该专家从头单独运行的成绩。独立基准、有状态适配版和真正融合版必须分别报告。

默认优先无状态专家（reset/observe/onDispatch 空实现）。静态派发可能消除空钩子，但必须通过编译或实测确认，不能在文档中承诺零开销。有状态专家的维护成本对每个回调都存在，应限制注册数量；未注册的候选不常驻在线系统。

## 4. 动作契约与算法边界

- 所有算子共享 M。整数容量、字节和缺口用 int64_t，不能用 int 表示 4 GiB。
- overflow 缺口 `max(0, tuple_size - (M - memory_used))`；只返回 SPILL，排除当前 INSERT 目标、非驻留分区及零大小分区。释放后必须能插入。
- miss 缺口由**目标完整 data_size**与当前空闲量求得；必须先确保容量，最后一项为 LOAD 当前目标。
- LOAD/SPILL 均为整分区；不得 LOAD 所属算子仍为 BUILD 的分区；所有中间动作后容量均合法。混合 BUILD/PROBE 算子可同时存在，不是全局同阶段。
- 磁盘分区的 INSERT 只追加新字节；不能假设每次追加重写历史分区。当前 key 映射 `key % P`，不引入外部 hash 模型。
- 已回传的动作是有序动作计划，引擎逐项执行，不承诺原子执行或失败回滚；不对多个专家动作投票/求均值/简单拼接。软保护 next_op 时仍须有足够替代容量；不允许为了保护下一个访问而拒绝当前必需 LOAD。
- 每个方法声明 tie-break，例如分数相同按 op_id、partition_id 升序。NN 特征/输出应有限，NaN/Inf 或不支持状态须走声明的确定性回退，回退开销计入成本。
- 无法完成合法计划属于错误，诊断验收应失败，不利用参考引擎静默忽略非法动作通过测试。形式合规不自动说明算法质量。

## 5. 离线比较、缓存与学习目标

统一执行接口只负责下一次回调动作。**完整总代价由外部评测器累积**；在线专家不能准确返回未发生的总成本，也不能读取真实 miss_penalty。已有历史统计只能标为观察到的统计或估计。

离线有两种问题，不得混用：

| 模式 | 状态与用途 | 边界 |
| --- | --- | --- |
| 独立在线重放 | 每个专家各自的引擎与专家记忆，逐个输入运行 | 可缓存前缀，但布局已不同；不能直接当同一个状态下的下一步标签 |
| 同状态候选比较 | 复制同一个引擎和相应专家状态，再分别应用合法候选动作 | 反事实分支仅在离线训练中存在，不能接进在线提交 |

缓存键至少包括协议/框架版本、源代码和权重 SHA、配置、输入前缀或快照身份、引擎布局、专家记忆及观察序号。命中必须能恢复完全相同状态。不能仅按操作序号、文件名或专家 ID 缓存。训练读取后续真实数据只用于教师标签/损失，输入特征仍受在线可见信息约束。

独立小网络采用**好专家偏好 + 实际案例成本**的混合监督；注明两项损失/权重、教师版本、训练样本来源、随机种子、CPU 导出误差。好的数学规则可做教师，但不能只模仿一个平均赢家，忽略尾部差例。全流程按输入文件/生成家族分组划分，避免同一流相邻回调随机拆进训练和测试。

后续树标签应在同一真实状态上比较候选动作的后果，采用有界离线 rollout 或案例贡献，并注明短视标签偏差。当前 miss 惩罚已在回调前触发，是该回调各候选的共同项，不能靠当前动作“消掉”；未来 miss 才可能受当前决策影响。

树输入不能依赖所有专家算完才得到的输出/成本；不得把训练 oracle 的最小成本、真实模式/种子或未来统计当特征。训练后需在其自身产生的真实轨迹上完整重放，检查状态分布变化；逐行标签准确率不是最终融合成绩。现有 R48/R54 eval 已用于开发，不作全新盲测声明。

过去提出的“全局均值 + 最近窗口均值 + 下一步估计”可作后续独立研究基线，但不是本规范默认在线实现。要在线维护所有影子专家时必须另报模拟/缓存/内存成本，遵守只看已到达信息；不能假定免费影子状态。先通过独立专家和轻量选择器验收，再考虑这个扩展。

## 6. 时间预算与选择器开销

官方比较成本（微秒）：`C = Total_IO_Time + miss_penalty * Miss_Count + Total_Decision_Time`。专家/树的真实额外决策时间必须小于其换来的 I/O 与 miss 成本节省，才能降低该例总成本；penalty 仅离线评分器可从输入读取。

另有每例实际进程墙时限制。当前保存题面为 60 秒；输入解析、启动、动作执行也影响墙时。模拟 I/O 不是实际 sleep，不能拿模拟总成本除以一百万判是否超时。正式环境未知，本机安全不构成官方机器时限保证。

组合成本需按同一计时边界核算：

```text
D_full = 官方状态快照/计时边界成本
       + 共享统计/所有启用专家 observe
       + 选择器特征与树推理/派发
       + 选中专家的特征、推理/规则、动作生成
       + 运行时检查/回退 + 所有启用专家 onDispatch
```

不得把特征或历史计算移到未计时的旁路获得虚假收益。getSystemState 的复制在参考计时边界内，保持原样；额外内部计时只用于诊断。构造/reset 初始化也要记实际进程墙时，不把首回调工作提前到构造后宣称全程序更快。

团队初始工程预算（待实测调整，不是赛题硬条件）：

| 项目 | 初始目标 |
| --- | --- |
| 最终候选数 | 2–4 个互补专家；不强行为凑数保留劣势方法 |
| 首版树 | 最大深度 4，优先至多 8 个无需额外全分区扫描的特征 |
| 门控/观察/派发预留 | 先以快速固定专家完整决策时间的 10% 作预算目标，真实 A/B 不满足时减特征/专家或拒绝融合；不是通过公式强行扣出的时间 |
| 全程序墙时余量 | 先用本机最长正式压力例 ≤45 秒作内部目标；必须同时报告相对60秒上限的余量及硬件，不能据此保证跨机器 |
| periodic | 无收益证据时固定空动作，统计维护仍计时；不为“每步选择”强行跑 NN |

廉价特征可包括 callback kind、free/M、当前 required/M、K/P、next_op 类型及其是否等于当前目标、合法可见的累计计数；任何分区占比、最大值、均值等若需 O(KP) 扫描，必须计入特征成本。共享一次扫描可研究，但不能同时给“纯状态专家”隐式增加未版本化的字段。

独立候选阶段也要加一个**相同动作的门控成本对照**：直接调用、固定派发、具有实际分支工作的深度4占位树，三者选相同专家。用动作序列核对后比较正式 Total_Decision_Time 与墙时。防止编译器把恒定树完全删除；同时公布保留工作的证据。该试验只能测开销，不代表已训练树或已证明融合有效。

若噪声掩盖小开销，报告区间和无法分辨，不把负差值称为“负开销”。超过目标不等于违反官方规则，但不得宣称满足本团队预留目标。每回调定时器本身有开销，不能随意加入生产策略作为预算中断器；也不能中途截断必需 SPILL/LOAD 动作。

## 7. 每个方法的交付清单

建议各成员在自己的源码分支使用 `src/experts/<method_id>/`，已有文件保持来源，可另建适配目录。公共入口/协议在 main；数据仅在 datasets。不要改其他成员分支。

| 文件 | 必须说明/提供 |
| --- | --- |
| `expert.hpp` | 唯一 namespace、上述接口、官方状态依赖；不重复定义官方类型 |
| `standalone.cpp` | 单专家 MySpillScheduler 适配，可并入官方框架本地构建；正式提交不能含 main |
| `manifest.json` | interface_version、method_id、expert_id（集成前可 null）、state_mode、adaptation_status、supported_ranges、tie_break、feature_schema、fallback、complexity、scratch/history/weights 内存字节、训练数据/种子/代码与权重 SHA、编译环境 |
| `README.md` | 算法、状态生命周期、成本/速度取舍、是否已适配、未通过项及复现入口 |
| `results/` 或固定链接 | 逐例/逐集/总体数据、源/框架/输入/评测器指纹、原始五项指标、时间和错误；不要只放一张均值表 |

`state_mode` 固定取 `stateless` 或 `callback_observed`；适配状态单列 `adaptation_status`，取 `not_adapted` 或 `adapted`。旧类回调内直接记候选动作的实现先标 `not_adapted`，不得在集成清单中启用；拆分完成并有第 8 节验收记录才能标 `adapted`，不能仅凭字段自我认证。无训练的方法训练字段为 null，不伪造权重来源。具体内存/参数数字须实测或按结构计算，别用“很小”替代。

manifest 的 interface_version 为字符串 `1.0`。支持范围至少列 K、P、memory_limit、phase、callback kinds，并分别说明 decide 的选择范围、observe/onDispatch 的安全范围，以及首回调整体排除条件；复杂度分别列 observe/decide/onDispatch。源文件 SHA 放在外部 manifest 或实验记录，避免自包含 SHA。ID 稳定映射与已注册专家总成本由集成负责人维护。

## 8. 接入验收与实验报告

1. **接口与合法性：** C++14 -O2、纯 CPU、标准库；官方三回调不变。覆盖溢出目标排除、恰好/略不足容量、多个 victim、4 GiB、零大小分区、BUILD/PROBE 混合、next 保护无替代空间、miss 末尾 LOAD、无 next、periodic 空动作。非法动作在诊断检查中必须失败。
2. **纯提案：** 同样快照/观察历史重复 decide 得同样动作；丢弃一个提案不改变后续选择；清 scratch 不改动作；不跨输入泄漏状态。不把 const 编译通过当充分证据。
3. **切换：** 固定 ID 模式与独立适配版逐动作等价；A/B交替、长时间未选后恢复、同一操作多回调、重复相同 next_op、回退与空动作通知均验证 observe/onDispatch 顺序与次数。未选专家不能记自己未执行动作。有状态方法的语义变化需单列。
4. **正确性和时延分开：** 独立物理重放/动作审计与正式无插桩计时分别执行。五字段公式校验不是动作合法性证明。旧 legacy_checker 不能证明新协议合法。
5. **性能：** 固定候选与输入后再计时，串行独占 CPU，无并行训练；相同构建选项/CPU/重复次数。每例保留全部运行与失败，报告 IO、miss、D_full、总成本、墙时、RSS。若只测部分输入，显著标 `partial`。
6. **尾部：** 逐例成本倍率的均值/P50/P90/worst、胜平负、失败数；同时列相对官方 Naive 和稳定规则的倍率。注明分位算法及样本单位。逐回调 P90 需单独诊断采样，不从总决策时间除次数伪造。小样本 nearest-rank P90 可能等于最大值，必须解释，不能把并列分位当证实可靠。
7. **公共评分：** 使用 main 当前评测器，记录 schema/SHA；默认遍历所有有数据的成员集合，每集单列，最后等权平均，空集列 skipped，坏非空集/失败不能静默丢弃。不同成员分支可能仍保存旧 schema；不得混用。封顶后的总分可能隐藏差异，还需未截顶逐例收益和成本倍率。
8. **训练/验收：** 训练选超参只用 train/开发划分；eval 用于报告后即视为已见，下一轮适当扩充新种子/分布家族。神经和非神经使用相同接口、数据版本和计时口径。非支配候选先保留，不因“用了网络”加分，也不因只快一点淘汰有明显总成本收益的方法。

本轮优先次序：统一此契约 → 单专家合法适配与小规模 CPU 筛查 → 补充组合与压力覆盖 → 选少量互补专家 → 训练/验证浅树及真实闭环轨迹。是否晋级以完整成本、尾部和时间余量共同决定。

## 9. 现有方法的迁移状态

R49/R53 的无历史规则可优先拆成唯一 namespace 的 Expert，再保留独立适配版做等价比较；旧文件不直接改写成新版本以覆盖历史证据。其他成员有状态类应先把回调中的候选生成副作用拆分到实际观察/最终动作通知，再逐项验收。本文发布时没有据此宣称任一旧方法已完成全套迁移。

后续最小实现已将R53 best-fit与R55 next-guard-fast适配为无状态专家，见 [源码分支的适配和验收范围](https://github.com/cyanneko/HuaweiHackathon/tree/source/cyanneko/src/experts)。其字面状态/导出动作检查不等于全流性能验收，不据此宣称有状态旧方法或训练选择器已完成。

有些成员分支保存了完整参考框架，而 main/source/cyanneko 的已发布方法是仅 Scheduler 类。成员框架必须核对协议和计时来源，不能因文件名叫 reference 就认定最新。正式输出保持原五项；专家 ID、切换次数、回退原因等写 stderr 或诊断文件，不能混入或重复官方指标。

契约未来新增共享特征、改生命周期或改候选语义时升级接口版本并记录迁移说明；不要悄悄要求其他成员按聊天口头变化修改。交接最少给出方法 ID/分支/commit、接口版本、数据 VERSION/指纹、实际已完成验收与尚未完成项。

可选ID104（naive_unique_max_fused）已完成冻结R59逐动作/导出typed验收，未测SDK接口D，不继承直接版性能，也不替换official_naive基线；固定101+104只作测试夹具，默认101/102仍保持。正式比较保持官方框架原样，提交仅MySpillScheduler实现；test_types/diagnostic仅本地验证，不能带入正式框架。R61小树的研究结果见赛前报告，不等同已发布默认融合策略。
