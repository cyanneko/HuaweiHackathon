# 运行前机制分析：共享改变概率与集合代价的不同路径

2026-10-30，写于Round11 observer运行前。源码依据是冻结的[R80](../round10/R80_next_hier_fast100_reference.cpp)，不是新的实验结论。已有描述性统计显示固定两条548/593分别为K=2和K=1，因此应明确单算子与多算子的不同解释。

## 单算子时，概率共享是向均匀的仿射收缩

设K=1，P为分区数，mᵢ为衰减后的next样本质量，T=Σmᵢ，a为该算子的share。R80的总先验质量为64：

```text
p_flat_i = (m_i + 64/P) / (T+64)
p_hier_i = ((1-a)*m_i + a*T/P + 64/P) / (T+64)
         = (1-a)*p_flat_i + a/P
```

这是代码公式的代数恒等式。在0≤a<1时，共享不会颠倒单算子内的**概率排序**；高于1/P的概率下降，低于1/P的概率上升。它仍可能改变实际驱逐结果，因为候选排序量还乘`1/R+1/W+100/sᵢ`，且子集比较包含对象大小、对象数和当前写费。不能仅看到某个热点概率下降，就认定它导致了不同驱逐。

## 无next保护项时，子集损失如何变化

仅考虑原代码使用频率路径、同一候选集合、没有被加上next巨大保护项的PROBE对象。令`c=1/R+1/W`，`Fᵢ=c*sᵢ+100`，原子集写系数为0.25：

```text
L_flat(S) = 64*sum_i p_flat_i*F_i + 0.25*sum_i s_i/W
L_hier(S) = (1-a)*L_flat(S)
          + 64*a/P*sum_i F_i
          + 0.25*a*sum_i s_i/W
```

因此共享除了改变相对概率，也在这个受限比较中改变了“有区分的热度”与“总驱逐字节/对象数”的相对权重。若子集释放量、对象数相同，新增项相同；若释放量不同，即便候选概率排序相同，最终子集也可能改变。该等式不适用于跨算子share不同、scan/refault/cycle分支、next保护项或不同候选池的完整比较；这些须从实际快照判定。

## 本轮要证伪的具体链条

1. 快照是否真的使用频率路径，是否有足够质量使share减弱？
2. flat/hier差异是否改变候选排名、前4覆盖或最终prune后的驱逐序列？
3. 若动作不同，实际写出字节和估计损失分别改变多少？需同时记录两种估计对两套动作的值，不能仅展示各自偏好的值。

该链条只解释共同状态下的局部选择。两例和少量快照不能证明完整轨迹收益、最优性或全部Zipf退化机制。以原R80为实际轨迹，flat反事实动作不执行；在线算法仍只接收合法状态。运行后若链条某环没有发生，要保留否定结果，不能临时换状态寻找支持。
