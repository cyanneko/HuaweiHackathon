解决的问题
旧严格循环识别器遇到不一致转移就丢失循环能力。
新算法保留主导循环顺序，在少量插入、跳项、重复、相邻交换后逐步降置信，
通过新观测恢复；不要求循环覆盖所有分区，也不要求分区等大。

算法机制
1. 每个分区维护两个候选后继和有界计数；孤立异常不清空主导后继。
   只用合法回调公开的当前/next PROBE及自身历史；相同序号去重。
   序号不连续时不添加直接边，避免把漏观测误当作真实相邻转移。
2. 提取长度至少4的主导循环。单边保守计数比例至少40%、支持至少6；
   循环整体计数比例至少60%，不再要求每条边都达到原版70%的纯度。
   计数会衰减，支持顺序变化后的重新学习。空间O(KP)，重建扫描O(KP)。
3. 每次先用既有循环顺序校验新观测，再更新边，防止先学习再评价自身。
   相位质量以31/32指数平滑；预热后达到75%启用，跌到约55%停用，形成迟滞。
   连续环外观测达到8次、锚点过期等也会停用，但暂时的图证据下降不立即删除顺序。
4. 按循环位置估算再访问先后，与原成本/热度规则按相位置信度混合。
   严格循环快捷路径和容量约束保留；没有可靠顺序时使用原p3规则。
   只预加载接口明确公开的目标，不读取完整未来、真实罚项或输入文件。

验证与实际局限
先在固定独立生成的20条fit循环诊断筛选，再在不同种子的20条validation×3选择n6。
fit扰动率5%，validation扰动率8%；各含32/64分区与B=1/17两种配置。
诊断输入通过官方格式/限制审计，没有按算法成绩筛选输入。
8%是生成器扰动触发概率；某些扰动会一次生成两个操作，并非精确的改动操作占比。

validation完整SDK成本相对p3的几何平均比值：
  插入0.555442；跳项0.534232；重复0.603797；相邻交换0.563256；
  混合0.615466；部分循环0.516436；非等大循环0.581443；
  相位反转0.989463；严格循环1.000012；IID随机1.000007。
20例整体比值0.670826，即几何平均下降32.917%。包含真实决策CPU耗时。
严格循环和IID两类对照的I/O、Hit、Miss均与p3完全相同；IID对照没有启用近似循环。
这些是受控诊断结果，不能推断所有负载均有同样收益或随机误报概率恒为0。
