# 从匿名Hit预测诊断到完整调度：下一步边界

状态：待机制与计算预算审阅，尚未生成新提交候选或执行新solver。

有限前缀结果支持联合估计含有next-only没有的信息，但不证明调度会改善。固定16步已接近充分MLE，学习一个优化器替代充分迭代没有当前证据。若继续，需要先建立可部署的强统计参照，才能公平检验学习校准。

## 必须独立解决的部署差距

- 已验证观察器在回调动作确定后汇总匿名Hit。在线估值需在本次选择前吸收合法的已发生信息，并在动作执行前记录将产生的驻留集合；不能将未来动作或未来Hit用于当前概率。
- 当前估计内核保存全历史不同驻留集合，四个前缀只到4096 PROBE。内存与重算不能随500万操作无限增长；必须先冻结有限窗口/分块或明确的集合上限及其统计含义，不能把截断后的结果称完整历史MLE。
- 充分估计的CPU数字是四次查询总和，不能直接当每回调开销。实际候选需要确定更新触发频率、无匿名Hit时的快路径，以及最坏合法输入的CPU测量。
- 先只更换概率估计，保持paired两个规划器、候选池、当前写项、next与相位处理不变。来源统计和2σ有效样本量如何匹配联合观测必须另行明确：匿名Hit软分配不是独立精确样本，不能直接增加旧sample_squares后宣传更高置信度。
- 仅全PROBE阶段使用已有被核查的集合观测契约；跨BUILD/PROBE混合阶段在未验证前保留旧估计。未观测普通Hit身份、真实概率、文件名、family、未来N、B或隐藏罚值不能进入线上输入。

## 初步推进顺序

1. 固定合法事件轨迹，检验有界历史相对现有16步估计损失多少信息及计算量；这个实验只决定是否值得适配，不能用新主测试选窗口。
2. 明确联合观测下的风险项。可先在相同规划器估值中使用新概率、沿用旧next样本风险项作为独立设计选择；它不自动成为联合估计的有效置信界，也不能保证更保守。必须核查门槛如何变化，不能同时偷偷换风险目标。
3. 若成立，再冻结一个完整候选，与原paired及同骨架统计参照做训练上的动作/字节审计和完整成本比较。需检验冷启动、一直Hit、B=1无匿名Hit、重复next、预取、跨算子、末尾没有新回调、内存极紧等真实回调边界。
4. 只有完整训练流有稳定增益、CPU/内存可接受，才进入新dev和一次冻结终检；AI校准必须在同统计骨架上提供额外收益。

该文档防止把有限前缀的概率改善直接包装成已实现的调度提升；尚不指定窗口长度、触发频率或新增参数网格。
