# 联合修正版：复杂度与时间限制核查

2026-10-30。用户询问当前联合版是否满足题目复杂度和耗时要求。本轮只读源码与既有结果，没有新增编译、求解器、训练或重复计时。对象为 `pure/return_risk_pooling100_v1.cpp`，SHA-256 `52ae25812a9863eae0774b2d45e837fd499506431650b8943ed6e4e979c76d2e`。

结论：单次决策的最坏复杂度上界符合题面建议；已有原72例及每例500万操作的dyna12例均低于60秒。尚不能据此保证所有合法输入在正式机器上都不超时。联合版增加了决策开销，其成绩收益另行判断。

同一题面限定 `K≤8`、`P≤64`、`N≤5,000,000`、`1≤B≤10,000`。当前解释版见 [STATEMENT_ENHANCED.md](../../STATEMENT_ENHANCED.md) 237–274行。

参考框架的模拟I/O仅累计成本，没有按模拟秒数实际等待。60秒判定对应真实进程经过时间。`Total_Decision_Time` 是回调计时区间的累计经过时间，包含 `getSystemState` 构造/状态复制与临时状态销毁，不是纯调度函数的专用CPU计时；输入解析、动作执行在该计时区间外。

## 静态复杂度

令 `n=KP≤512`，`v≤n` 为一次候选释放的分区数量，`C` 为实际回调次数。

| 部分 | 上界及源码依据 |
|---|---|
| 新增风险统计 | `before` 的算子检查为 `O(K)`，区间统计/衰减为 `O(n)`；`after` 更新为 `O(v)`，必要同步为 `O(n)`。见源码21–81行。 |
| 算子与分区联合估值 | 先线性汇总算子D/Z，再线性遍历候选差集；每对象leave-one-out直接减自身，不再扫描同算子的所有对象。`future` 为 `O(n)`，见83–104行。 |
| 候选生成 | 收集分区 `O(n)`；top4的 `partial_sort` 为 `O(n log 4)`，仅枚举至多15个非空子集，每个至多4项。见286–339行。 |
| 释放多个分区 | BUILD无访问信息分支可全排序 `O(n log n)`；其他分支建堆并弹出v项，`O(n+v log n)`。见340–364行。 |
| 候选比较 | 只保留两个既有proposal，常数次生成；裁剪、sign数组与均值/风险比较均线性。见370–432行。 |

因此每回调最坏上界仍为 **`O(n log n)`**，常见单受害者路径为 `O(n)`。新增联合修正只增加线性扫描和常数计算；没有枚举全部分区子集或新增二次嵌套搜索。总决策上界可写作 `O(C·n log n)`；原框架每个INSERT/PROBE至多一次事件回调和一次周期回调，所以 `C=O(N)`，整个流的保守上界为 `O(N·KP·log(KP))`。实际回调数量会随Miss、预取和B改变。

旧next概率的衰减按至少256个PROBE时钟步执行，全流该部分为 `O(n·(1+Q/256))`，Q为PROBE数；不能把新增风险核也误称为每256步才扫描。新增风险核在有未知访问区间的回调中可能扫描全部n个分区。

可变历史、候选、动作、差集空间均为 `O(n)`，风险核另有固定512槽数组。既有部署检查测得风险对象本身8,768字节；该数不是整个调度器、框架或进程的峰值内存。源码的 `refreshCore` 没有调用，不应把其遗留逻辑解释为运行中的新核心机制。

| 测试范围 | 联合版每例平均累计决策时间 | 最大累计决策时间 | 最大真实wall | 超60秒 |

| dyna12例，每例500万操作，历史每方法3遍 | 13.855487秒 | 24.393397秒 | 31.081533秒 | 0 |

原72的最大操作数为1,048,576；dyna覆盖 `K∈{2,4,8}`、`P∈{32,64}`、`B∈{31,127,1000}`。dyna最慢的是 `dev_fast_shared_08` 第3次，`N=5,000,000,K=8,P=64,B=31`，即已经同时覆盖操作数和分区数上限；31.08秒约为60秒限额的51.8%。三次历史计时不等于36个独立数据场景。今后默认单遍，未为本问题重跑。

原72原算法的平均累计决策时间为0.093241秒，联合版增加35.72%；dyna的对应均值为9.283487秒和13.855487秒，均值之比增加49.25%。dyna旧报告的43.18%是先逐例取时间比再平均，口径不同，不能混用。两方法轨迹和回调数也不同，这些差异不是独立统计内核的纯开销测量。

计时平台为AMD Ryzen 5 7535U、WSL2、g++11.4，C++14/O2、调度器单线程。仅有任务实验锁，不保证整宿主独占、频率固定；正式CPU具体型号没有给出。当前联合版的这些大规模结果未覆盖 `B=1` 与其他高回调频率组合，旧版本的压力测试不能替代此源码的证据。因此可说“已测规模达标”，不能说“全部最坏输入保证60秒内”。

原72的两方法均分仅差0.000085043；运行不超时不代表联合版整体更优，当前仍未据该分差晋升。
