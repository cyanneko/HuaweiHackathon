# R65：30 例开发样本（未晋升）

这是按元数据挑选的部分开发样本：三成员各 10 例，共 30 例，仅比较 Naive、R63、R65，每格单次测量。90 条 EXITED 记录含原九格精确复用与 81 格新测，不是 90 次同批新测量。[原九格报告](../r65_targeted_exploration_20261030/README.md) 保持独立。

父数据实际 eval/VERSION 为 cyanneko 0.6.0、liunianwww 0.1.0、Vanius0525 0.1.0；父集合共 48+528+209=785 例。本样本身份单独使用 cases30 SHA256，不用合成的 partial 标记冒充 VERSION。三个强制案例此前已经曝光，不能称盲测，也不能推及完整集合或竞赛排名。

主分：VAL<=0 或 BASE<=0 时逐例记 0；其余 clamp(10*(1-VAL/BASE),0,10)。先对每成员十例求未封顶 SUM，再对三成员等权平均；不除以 10，不设成员 50 分封顶。

n=30 时，普通 median 取排序后第 15、16 项均值；nearest-rank P50 取第 ceil(0.5*n)=15 项，P90 取第 ceil(0.9*n)=27 项（均从 1 开始）。原报告 JSON 明确使用 nearest-rank；原 Markdown 的通用 P50 标签也对应该值，原报告未被改写。三方法的两种 P50 均在 JSON 中保留。

最差成本比来自 edges_all_empty：R65 1.44 / Naive 0.68 微秒 = 2.117647058823529；两者 IO=0、Miss=0，成本完全来自正式 D。单次很小的绝对差值不能确立稳定回退，也不能断言噪声成因。edges_int64 成本为 Naive 的 1.6286208292470077 倍，比 R63 高 39.02701327792138%；growth 为 Naive 的 1.4335969372369732 倍，比 R63 高 3.278956035725633%。全部逐例结果及最坏例保持可见。

正式 D 是未修改的官方内部 chrono 策略回调耗时（微秒），与 GNU 进程 CPU、elapsed、父进程 wall 及诊断版本计时不同。GNU 显示 0.00 秒不能当作零耗时优势；本包不作 D 稳定性结论。

results.json 保留 90 行、输入/程序/框架/参数四 SHA、cache key、旧九格来源 scope 与精确复用对应、全部逐例与尾部统计。per_case.csv 为原文件字节。raw/ 的 90 份 stdout 逐字保留；90 份 stderr 仅移除本机命令/路径行，分别记录原始与公开 SHA。原 result.json 仅保留来源 SHA 和对应公开 raw 相对路径，不发布进程或本机位置记录。summary.json 是独立只读复核的净化副本。无 PDF、ELF、输入数据或框架副本；本次仅整理已有证据，没有重新执行实验。
