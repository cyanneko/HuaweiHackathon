# 官方 8 组用例提示与迭代调整

更新日期：2026-10-30。

## 新证据及适用边界

用户本轮转述出题人提示：

> 1. 总共 8 组用例。
> 2. 关注一般随机情况就行，用例主要是模拟数据量较大或者数据倾斜场景的 hashjoin。

这是本次调整的依据，尚未获得 8 组的输入、种子、规模或具体分布。不能据此推定 8 组各对应一种模式，也不能推定全部服从某个 Zipf 参数。此前大量极端反例仍有诊断价值，但其数量占比不能当作正式评测分布。

## 已决定的调整

1. 按用户最新要求，当前优先改进离线可行解质量、核查官方基线路径覆盖并调研离线求解原始论文；暂停新增 NN 训练及参数扫描。可验证标签和轻量网络仍是后续方向，须先解决教师质量问题。小规模 exact 和 pair-fits 等案例只校准求解器及既有训练链路；不继续以新增极端构造为主要投入。
2. 下一轮重点放在普通随机、均匀访问、大工作集和数据倾斜。从现有数据元信息选择 24 个相关案例作为新开发抽样清单；不能依据方案成绩选择案例。缺少的覆盖先登记，再生成独立种子数据。
3. 既有 30 例及其结果保持冻结。最多另外保留 8 个已有边界/退化案例作为防回归集合，与新主场景结果分开报告；不追溯替换旧案例来改善历史成绩。
4. Handler 继续独立的非网络启发式支线。当前 BBP 五例是机制筛查，通过后仍须在普通随机/倾斜样本上验证，不能凭针对性反例的改善推广。
5. 所有部署候选仍满足官方类接口、C++14/O2、CPU-only、在线可见性。正常命中不可观测等框架限制不变；离线未来信息只用于教师标签。

以上 24/8 数量是本地快速迭代的资源分配，不是对官方用例比例的估计。

## 数据必须分开的轴

| 维度 | 要区分的情况 | 目的 |
|---|---|---|
| 操作数量 | 短校准轨迹、较长随机序列 | 检查累计决策开销、内存与长时间状态变化 |
| 工作集压力 | 总 Build 字节 / M 接近 1、中度超出、显著超出 | 区分偶发压力与持续换入换出 |
| 分区大小 | 近均匀、Build 分区大小倾斜 | 大分区会释放更多空间，也会产生更大 I/O |
| Probe 分布 | 近均匀、稳定热点/倾斜 | 学习复用机会，避免仅按字节认定热度 |
| 二者关系 | 大分区更热、大小与热度独立；少量反向关系作诊断 | 防止把特定相关性当作普遍规律 |
| 算子阶段 | 常规 Build 后 Probe、合理多算子重叠 | 保留真实可表达场景的阶段差异 |
| 回调负载 | 不同周期 B、不同 miss/overflow 频率 | 同样 N 不一定带来相同调度成本 |

倾斜生成必须保留官方合法性：每个分区可装入内存、INSERT 大小和键范围、阶段顺序、声明计数及 N 一致。裁剪超大分区会改变预期分布，必须记录实际大小/热度集中度，而非只记生成器的目标参数。

## 训练与离线求解

- 现有 12 个真实 train 的交付继续使用，但先用于合法性和链路校准。后续扩大训练前根据元信息筛出普通随机/倾斜案例，不把所有角落案例等量堆进主要训练集。
- 离线求解预算不足时，保留完整可回放 baseline 和 best-found witness；不把截断路径或 beam 的累计前缀成本冒充完整总代价/最优解。
- 长数据的后续选项是从完整因果前缀重建状态，在少量锚点做有预算的后缀比较。任何短视窗标签必须显式标识其范围，不能当作全局最优；首版先完成已有全轨迹小 pilot，避免扩张阻塞交付。
- 划分以完整轨迹/种子为单位。已曝光的 30 例仍是开发回归，不能训练后再称独立测试。长轨迹产生更多状态不意味着应自动获得更高的训练权重；扩大训练时记录每轨迹标签量和采样权重。
- 模型损失、教师动作覆盖率和闭环调度结果分别报告；更好 imitation 不等于更好的比赛分数。

## 评测与时间

仓库[评测协议](../evaluation/README.md)及[接口来源说明](EXPERT_INTERFACE_V1.md#1-目的和依据)记录以下代价定义：

`Total_Score = Total_IO_Time + miss_penalty * Miss_Count + Total_Decision_Time`。

同一保存版本给出单例 60 秒墙上时间和最高 5,000,000 条操作。新提示没有取消这些约束，仍需关注长序列耗时；不能把框架的模拟 I/O 数值当成实际磁盘读写耗时。D 由框架时钟测量，实际值受运行环境影响。

- 新 24 例逐例列出 Total_Score、IO、miss、D、墙上耗时和对 Naive 的倍率，报告普通中位数、P90、最差值及退化例；已有报告的 nearest-rank P50 保留并明确命名。
- 较长输入先分级做速度筛查，在无竞争窗口记录完整调度成本，包括历史更新、扫描、候选生成和网络推理。
- 公共仓库计分仍沿用已约定的成员聚合方式，单例全部保留；新场景筛查单独命名，不能与不同 suite 的旧主分直接排名。
- 不因“8 组”修改单例公式，也不把本地 24 例总分等同正式 8 组总分。按用户此前要求，研究比较继续保留未封顶结果，不以达到 50 分为优化停止条件。

### 用户再次明确：超过 50 分仍继续优化

用户在同日补充：不要盯着 50 分的满分，目标依旧是分越高越好，超过 50 分也用于展示性能优势。因此：

- 研发主报告、方案选择及是否继续改进均看未封顶得分，不用 `min(50, score_sum)` 抹平更优方案之间的差异。既有公共成员聚合协议不变。
- 若官方评分版本仍规定封顶，将该口径单独列出；未封顶研发得分不得冒充官方最终成绩。
- 超过 50 分的性能比较仍须固定测试集合、版本、基线及聚合协议。增加用例数量会改变总分尺度，不能据此声称算法进步。
- 同时保留逐例 Total_Score 倍率、成本下降比例、IO、miss、D、中位数、P90 和最差值。单例 clamp 后都记 0 分的负例也须展示其实际退化幅度。
- 不以未封顶得分替换离线教师的物理成本目标，教师仍最小化完整轨迹的 IO 加 miss 惩罚；最终部署评价另加实际测量的 D。
