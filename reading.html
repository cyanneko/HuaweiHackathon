面向动态倾斜的分层热度调度

热点会迁移，分区大小不一，普通Hit又并非完全可见。我们的目标，是在有限内存里持续做出值得的驻留选择。

02 / 问题与目标

优化对象是成本，不只是 Miss

一次小分区 Miss 和一次大分区 Miss，可能相差几个数量级的搬运费用。

真实计分成本C = BreadR + BwriteW + λ · Nmiss + DR、W：读写带宽（字节/μs）；B：实际搬运字节；λ：输入中的真实Miss罚值；D：回调决策时间。

降低 Miss 有价值，但要同时看读写字节。我们可以让多个便宜的冷请求 Miss，却避免一个昂贵分区反复被逐出；反过来，盲目保护大分区也可能挤走大量更常用的小分区。

三个独立的量它决定什么策略应该怎样使用
分区大小 s容量占用、读写成本进入搬运成本和装填约束
PROBE 概率 p未来驻留收益从合法观测估计，不由大小推断
BUILD 增长后续内存压力影响保留机会，不等同于未来热度

调度器可以改变什么

合法动作为整分区 SPILL 与 LOAD。调度器不能拆热点分区、换哈希函数、压缩数据、重排请求或把查询改成批处理。冷请求也不能被拒绝准入。

线上估值代理λ̃ = 100 μs真实λ不在SystemState中；100只用于算法内部估值，评分始终使用各输入自己的真实λ。
最关键的转向

从“哪块数据看起来最冷”，转向“释放足够空间时，牺牲哪个集合的总成本最低”。

从挑一个受害者，到选择一组代价

最初的直觉很直接：优先写出小分区，保护明确的下一次访问，再用频率与最近性避免驱逐热点。真正的困难在于：容量按字节约束，动作却只能以整分区为单位。

局部动作

少写一点，是否一定更便宜

更小的当前写量可能改变最终留在内存的集合，增加之后的读回；需要比较完整执行轨迹。

候选与选择

好动作进了候选池，也可能被排错

扩展covering-singleton候选没有稳定晋升。问题不只在搜索范围，也在热度估值是否偏向可见Miss。

大小与热度

总价值排序不能直接取代密度排序

R10直接按整对象总价值排序，最坏训练例相对R80成本达23.565倍。后续保留单位空间估值，再在可行子集中比较总损失。

驻留与周转

软热点核心是有价值的假设，但这版没有获胜

R12少量保护带来了更少Miss，却可能导致更大分区反复搬运；最终没有引入该核心/尾部折扣。

BUILD也要看后续效果

最新独立BuildBestFit对照只改冷启动BUILD的单受害者选择：dyna平均成本比R81高0.01435%，stat低0.08019%，方向相反且幅度很小，最终未采用。

BuildBestFit为同学已归档的22例独立对照，不是此次新增实验，也不混入旧84例主榜。它只保证局部可行单对象的写量选择，不保证整个轨迹更优。

HASH JOIN / FINAL R81 观测边界
06 / 观测边界

没有被看见，不等于没有被访问

普通 Hit 常常不暴露身份；Miss 一定暴露目标。直接累计可见访问，会把调度策略造成的缺页当成真实热度。

信息来源可获得的信息在当前算法中的用途
累计 Hit / Miss总请求进度，无完整Hit身份构造PROBE逻辑时钟 q
periodic 与 Miss 回调的 next下一条请求的算子与分区去重采样，更新概率估计
当前 Miss 与驱逐后重访哪个盘上分区被再次需要更新重访风险与历史回退
分区大小、阶段、位置当前可合法操作的状态成本计算、容量与阶段约束
时钟与去重q = Hit + Miss，　next 的序号 = q + 1同一个next可能在多个回调中出现；只接收序号大于已采样序号的请求。连续两次同key但序号不同，仍是两个样本。

为什么不只统计 Miss

驻留成功的热点少产生Miss，反而不再可见。Miss更适合描述“驱逐后损失”，不能直接替代无偏访问频率。

为什么保留 next 样本

它在部分Hit之前就暴露请求，能补足只看Miss的偏差。固定独立请求下更易解释；动态相关流仍需衰减与稳健估计。

实现与统计解释分开

R81 将 periodic 和 Miss 后暴露的 next 合并去重后采样，没有为两类样本设置独立权重。当前 Miss 不直接再加入这条概率采样流，但会更新重访与历史状态。这个区分避免了简单重复计数，也保留了周转反馈。

256 / 2048按PROBE序号计时。概率状态对齐到t=max(q, last_next_ordinal)，已暴露next时可为q+1；重访风险仍按q。二者都不是墙钟时间。

追问 / 综合集 3.0

全局倾斜，是否真的意味着分区热度可学习

保持父规格和BUILD种子，重建全部PROBE。显式保证每个算子内部也有概率差异，防止“只有算子冷热不同，算子内仍接近均匀”。540 train、72 eval。

三种随机偏斜，覆盖不同形状

Hotspot

少量热门分区，配合冷长尾。检验热点保留与冷请求周转。

Zipf

访问概率按秩衰减。检验多层次热度与容量装填的相互作用。

Lognormal

连续、非规则的概率差异。减少策略只适配简单头部结构的机会。

3.0 的偏斜度验收TV(p, uniform) = ½ ∑j | pj − 1P |TV为总变差距离，越大越偏离均匀。目标分布要求≥0.20，实际采样频率要求≥0.10；这是数据设计阈值。

均匀请求没有可学习的分区概率差异，但大小和搬运成本仍可不同。移出主测是任务聚焦，并不意味着这类调度问题必然简单。

09 / 数据生成策略

把“随机”拆成可控制、可检查的设计

生成器的职责是制造有解释力的变化，而不仅是延长操作流。

01物理规格算子/分区数、容量、大小、带宽
02BUILD结构增长、最终大小与阶段布局
03PROBE分布算子份额、条件热度、热点迁移
04验收与固定逐行合法性、实际分布、种子与SHA
生成与估计共同面对的分解p(i,j,t) = πi(t) · θij(t)算子份额与算子内偏斜是两个维度；全局分布偏斜，并不能保证每个算子内部也有热点。

示意：行的总量不同，但每行内部一样；算子内没有可学习的分区差异。

颜色越深表示联合请求概率越大。数值仅演示分解，不是新增生成数据或实测。

一个关键反例

若π=(0.65,0.20,0.10,0.05)，每个算子内部θ都均匀，整体已有明显倾斜，但仍无法区分同算子的分区。final3.0因此进一步要求算子内偏斜；dyna则让π随时间变化。

为什么要分开固定BUILD与PROBE

final3.0保留父规格与BUILD种子，重新生成PROBE，便于追问“变化来自热度还是物理结构”。同时记录目标概率与实际采样频率，避免生成配置写着偏斜，落地样本却接近均匀。

stat进一步把潜在随机过程下放到分区，用全局操作时钟每64步更新；大小、BUILD、PROBE使用不同随机流。它没有手工设定算子热度层，因而也能检验分层估计是否依赖生成器的假设；容量与预算仍可能造成耦合。

快速响应算子，稳定估计分区

记K为算子数、P为每算子的分区数。每个去重next样本分别更新快算子质量Fi与慢分区质量mij，Mi=Σjmij。

① 按PROBE间隔衰减Fi ← Fi·2−Δq/256，　mij ← mij·2−Δq/2048对应去重next样本加1；其余状态按需衰减到当前概率时钟。
② 算子边际概率π̂i = Fi + 64/K∑kFk + 64较短窗口帮助算子份额跟随动态热点。
③ 算子内条件概率θ̂ij = (1−αi)mij + αiMi/P + 64/(KP)Mi + 64/K较长窗口减少分区估计抖动；α随分区差异与有效观测量调整。
p̂ij = π̂i · θ̂ij有相同分区偏好的两个算子，也可以因当前活跃度不同而获得不同驻留价值。
R81保留的先验

快、慢两层的总先验都为64。后来R85A尝试将快先验降为约8.009，R87再尝试快慢专家混合；它们是独立对照，没有进入最终提交。

概率不按分区大小分配。大小进入后面的成本与容量规划，避免把“大”直接当成“热”。

BUILD、Miss 与预取，各有自己的职责

回调当前行为
onMemoryOverflow更新证据，排除当前INSERT目标，按缺口选择SPILL并剪除冗余动作。
onPartitionMiss结束目标的盘上重访观察；释放足够空间后，必须LOAD目标整分区。
onPeriodicAdjust首个Overflow/Miss启用调度器后才更新next并考虑预取；此前直接返回。

预取：明确会用，还要考虑是否额外驱逐

若目标已在内存、不是PROBE阶段或大于总内存，就不预取。空闲空间足够时可LOAD；若需要额外驱逐，只有已确认的等大小循环分支会继续。这样保留普通Miss回调带来的后续信息。

重访风险：为历史与特殊分支保留后备信息

盘上暴露与事件衰减E ← E e−Δq/τ + aτ(1−e−Δq/τ)，　N ← N e−Δq/τ
μ = (E+64)/(N+1)，　r = 64/(64+μ)a为正在盘上观察的分区数；确认驱逐后开始观察，Miss计事件，预取读回只结束暴露。分区τ=512、算子τ=128，是时间常数而非半衰期。

在历史回退分支，周期覆盖率不足0.75时，可见历史权重为0.25，其余结合分区/算子重访风险；覆盖率≥0.75时权重切为1，完全采用可见历史。普通随机PROBE主路径直接使用层次概率，并不是把风险分数再叠加一次。

已确定会在BUILD内落盘的分区首次写出 a + 后续追加 b = 最终分区大小提前落盘不额外增加这部分累计写字节；改变的是占用内存的时间、挤走谁，以及谁能留到PROBE。

五个真正改变方向的教训

01

候选更丰富，不保证选得更好

covering-singleton和小树扩展没有稳定晋升。好动作进候选池之后，仍可能被有偏估值排错；因此先改善观测与估值，再扩搜索。

减少 Miss，可能付出更大的读写代价

R12的train519比R80少833次Miss，按该例真实罚值只省0.099127秒，却多7.346876秒模拟IO费用，净物理成本增加约12.63%。软核心的直觉需要周转字节验证。

改成总价值排序，会改变整个可行集合

R10 value_rank在固定训练面板最坏单例物理成本约为R80的23.565倍。成本×概率有用，但移除单位空间归一化，会改变候选入口和整分区装填。
