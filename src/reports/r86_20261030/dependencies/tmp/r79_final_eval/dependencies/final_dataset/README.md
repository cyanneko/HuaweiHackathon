# final_dataset 2.1.0 · 大数据量与访问倾斜 Hash Join

当前主测试为 **72 例：Zipf 28、热点混合 28、对数正态 16**，全部逐例等权，以平均分（0–10）统计和比较。按用户明确的场景要求，退出主测试的是缺少固定热度差异的均匀独立请求；保留非均匀的独立随机请求。正式8例的目标均分6.25对应Level 1封顶50，本地达到6.25不保证隐藏测试达到目标。

本版保留2.0.0中的36个倾斜测试及原500训练的输入、元数据、种子和文件名原字节，再按生成前冻结的配方新增36测试、270训练，没有按算法得分或运行时间挑选/替换案例。旧分布成绩曾被查看；整体混合了已曝光回归输入和新输入，因此不把2.1.0称为未见盲测。新旧版本均分的差异包含测试组成变化，不能报告为算法改进。

## 三种分布的含义

令 q=K×P 为全部算子的分区数。每例先生成一组固定概率，然后逐次独立抽取PROBE目标；独立表示本次抽取不依赖上次结果，**不表示每个分区概率相同**。例如两个分区概率为0.8和0.2，独立抽取仍会产生长期80%/20%的热度差异。

| 分布 | 当前生成方式 | 能考察的取舍 | 主测试 | 推荐训练 |
| --- | --- | --- | ---: | ---: |
| `random_zipf` | 按排名r赋权重1/r^α，再随机打乱分区排名并归一化；α越大，头部越集中 | 少数高频分区与大量低频分区之间的驻留选择 | 28 | 216 |
| `random_hotspot` | 随机选一组热点，分给它们总概率h；热点内部均分h，其余分区均分1−h | 是否保留稳定热点，以及如何为冷请求腾空间 | 28 | 216 |
| `random_lognormal` | 每个分区抽取Z~Normal(0,σ²)，令权重为exp(Z)，再归一化；σ越大通常越不均匀 | 没有明确冷热分界、热度连续变化时的收益/空间取舍 | 16 | 108 |

热度结构可估计，不意味着能预测每次独立请求，也不保证AI优于频率统计规则。实际调度器仅能使用官方回调暴露的信息，不能直接读取概率、家族标签或完整未来请求。更强倾斜也不必然带来更高得分：大热门分区不能同时驻留时仍可能频繁换入换出。

分区字节量与PROBE热度分别抽样。Zipf的构建大小也按独立打乱的排名生成；热点的构建大小采用对数正态权重；对数正态家族的两侧分别抽样。容量裁剪和有限样本会影响实际分布，应看清单中的观测统计，不假定“大分区就是热分区”。被移出的均匀请求案例同样可能有构建大小差异；移出依据是本轮要求聚焦访问热度，而非声称这些案例没有任何优化空间。

## 组成、隔离与评分

| 当前位置 | 数量 | 用途 |
| --- | ---: | --- |
| `eval/` | 72 | 主均分：三种非均匀独立请求，每例等权 |
| `diagnostics/` | 1 | 原`eval_048_one_byte_over`容量边界，仅检查正确性，不计主均分 |
| `train/` | 770 | 保留2.0.0的500训练原件并新增270；旧均匀及边界训练不属于推荐训练 |
| 推荐训练清单 | 540 | 仅三种新合成倾斜训练，可单独导出；不含任何旧eval |

从当前eval移除12个`random_uniform`及1个`empty_partition_probe`。后者在强制首次访问空分区之后也使用均匀请求，因此一起退出。它们的准确路径和原哈希写在`selection.json`，旧输入可从父提交`53e7aed05bad46aac4048950d9f8aedef020ef8d`恢复。容量边界原件移动到`diagnostics/`；它的sidecar仍保留历史`split=eval`，当前归属以manifest的`diagnostics`和物理目录为准。

主指标是72例的平均分：每例、每重复先按官方规则归一化，再对重复取平均，最后对72例等权平均；评分规则仍为`case-mean-v1`。家族占比为28/72、28/72、16/72，保留父版本的家族比例再逐类翻倍，并非老师给定比例。不要另作三家族等权平均替代主指标。可附家族均分用于诊断；失败和超时不能从分母剔除。见[评分标准](../evaluation/MEMBER_SCORING.md)。

原500训练中，120例复用三方原train（2/70/48），380例为原新合成训练。推荐清单包括其中270例静态非均匀请求和本次新增270例，共540例；不使用任何旧eval训练。训练、主测试和诊断在原始字节、规范化操作流、`key % P`分区语义三个层面均无重复。新增306例还与父版全部550例比较，包括移出的均匀请求及边界案例。

保留部分与三方历史1625例及1.0.0的隔离沿用2.0.0完整审核，经本轮原字节复核绑定；新增部分未逐操作重扫全部其他历史集合，不能扩大宣称该隔离范围。

## 已核对规模与覆盖限制

| 规模 | 主测试72例 | 推荐训练540例 |
| --- | ---: | ---: |
| 总操作数 | 22,528,629 | 78,112,569 |
| 单例操作数最小 / 中位 / 最大 | 65,614 / 207,771.5 / 1,048,576 | 33,493 / 104,381.5 / 1,048,576 |
| 至少65,536操作 | 72 | 467 |
| 至少262,144操作 | 32 | 38 |
| 至少1,000,000操作 | 3 | 5 |

新增270训练+36测试全部至少65,536条操作，最大1,048,576；新增百万级案例全部K=8、P=64。新增内存M覆盖64/128/256/512 MiB及1/2/4 GiB，构建压力按1.15–1.7、1.7–2.7、2.7–4三档取样，热度强度也分温和/中等/较强三档。规格、种子、数值范围在`expansion.json`生成前冻结，数量上保持各家族比例，不按某算法表现偏向容易场景。

INSERT是真实操作记录，但文件只记录size字段，不存储对应大小的实际载荷；超内存的构建字节量与很多操作记录是两种不同的规模。实际输入字节量、构建字节量和操作数见`manifest.json`与`validation.json`。 全部843份输入文本共2,329,150,935字节；其中主测试474,874,705字节，推荐训练1,661,641,164字节。单文件最大22,856,498字节。

原题硬范围为K=1–8、P=2–64、M=64MiB–4GiB、N=1–5,000,000、W/R=1–10,000、miss_penalty=1–1,000、B=1–10,000、key=0–10^9、INSERT size=1–1MiB。每算子INSERT须在唯一SWITCH之前、PROBE须在其后，声明计数须一致；每分区累计字节量不超过M。新常规生成器进一步将每分区限制为0.8M。独立审核逐项检查这些约束，不因分布标签而放宽。

每例实际墙钟时间上限是60秒，超限按原题该例得0；官方对单次回调复杂度O(KP log KP)给的是建议，不能误写成输入硬限制。参考程序以整数/浮点运算模拟I/O成本，并不按模拟I/O时间sleep，因此不能把模拟总成本直接换成实际运行秒数。按用户要求先发布数据和输入审核结果，本次发布时参考程序的运行检查尚未执行。发布后将用官方Naive检查72个eval、5个百万级train及1个诊断的单次完成情况、输出协议和60秒超时，结果记录在本地，若无问题不再更新数据分支；本机参考程序通过也不保证另一算法或官方机器满足时限。正式比较仍需同环境复测候选并计入全部决策开销；不能丢弃超时案例后平均成功部分。

当前仍全部采用INSERT全局随机交错→所有算子SWITCH→随机PROBE，单个完整用例内概率固定，不模拟热点迁移或跨算子BUILD/PROBE重叠。没有5,000,000操作上限案例，没有系统控制大小与热度正/负相关。家族还同时改变构建大小分布，因此家族均分不是仅改变请求分布的因果比较；旧版Zipf大分区常达到0.8M的观察见[分布诊断](../evaluation/DISTRIBUTION_DIAGNOSTICS_20261030.md)。

三种分布提供可比较的热度差异，但尚不能证明足以区分所有算法，也不能证明最优均分可达6.25。它们是合成设计选择，不是官方隐藏分布的估计。后续机制实验应在新train/dev固定大小、压力和成本，仅替换Probe分布作配对比较，再单独考察动态热点和合法阶段交错；这些实验本版尚未实现。

## 使用与核验

Python 3.10+，仅标准库，从仓库根运行：

```sh
python -B final_dataset/tools/verify.py
python -B -m unittest discover -s final_dataset/tools/tests -v
python -B final_dataset/tools/build.py
python -B final_dataset/tools/build.py --training-only --out ../final_dataset-v21-train
```

`verify.py`检查843对输入/元数据的原始哈希、精确文件集合、来源、配方和筛选规则；独立逐操作审核270个新增训练、72个主测试及1个诊断，共343例。500个未改变的训练输入，其合法性在原始字节复核后继承2.0.0完整审核，区别写在`validation.json`。

当前`build.py`是冻结数据的校验/导出入口，需要完整2.1.0源包；默认核对现有文件，也可用`--out`完整复制或用`--training-only`导出540例推荐训练。它不从零生成、不下载、不换种子，不覆盖不同字节的文件。完整导出后用原仓库的`verify.py --package <输出目录>`重新核验。原2.0.0生成器和`build_v2.py`保留未改，历史重建应在固定父提交的独立检出中运行，避免旧构建器覆盖当前版本。

`selection.json`记录保留、删除、移动、增加及推荐训练路径；`recipe.json`保留722项生成规格（650训练+72测试）及1项诊断原规格；`manifest.json`记录842项train/eval及独立诊断条目；`provenance/v2.0.0/`保留父版本的配方、清单和审核原字节。新增306项另见`expansion.json`和`expansion_manifest.json`。

重建新增输入可运行`python -B final_dataset/tools/expand_v21.py --generate --jobs 2`，读取固定配方并拒绝覆盖不一致字节。生成期间发现原整数分配器大量扫描零增量项，引入`fast_allocation.py`作等价加速；400组分配对照及中断前25个完整案例的输入/metadata逐字重放通过。初始规格保存在`provenance/v2.1-initial-plan/expansion.json`，最终配方验证306项seed/spec完全不变，同时记录加速实现哈希。原`random_workloads.py`未修改，结果仍可用其慢速分配器复现。

评测72例主测试，先把官方Naive命令数组写入`baseline-command.json`，并提供已接入同一官方兼容框架的solver：

```sh
python evaluation/evaluate.py --datasets-root . --members final_dataset --repeats 3 --baseline-command-file baseline-command.json --baseline-kind official-naive --out results/final-v21.json --command ./build/solver "{input}"
```

评测器递归发现`final_dataset/eval/`，不会扫描相邻`diagnostics/`。本包位于仓库根部，需显式选取，避免与`datasets/`三方原集合重复计权。旧50例结果继续绑定2.0.0，不能改版本标签冒充本版完整结果；比较需使用同一版本与集合指纹。本次先发布调整、生成和输入审核结果；参考程序运行检查待发布后执行，没有运行候选算法比较或训练模型。

后续运行检查使用从[官方公开接口](https://www.chaspark.com/chasiwu/v1/content/races/question/detail/1326693349800046592)提取的Naive完整参考程序，源文件SHA-256为`177e41584848e920dba7d4ddc5e3696d15bb0395ce43c5714a57a36b3a580835`，以`g++ -std=c++14 -O2`编译。通过`tools/runtime_smoke.py --reference-source <参考源码> --executable <编译产物> --out <报告>`可复查；源码身份、编译器、硬件和每例墙时写入报告。它检查参考程序完成情况及输出协议，不替代独立动作轨迹审核。
