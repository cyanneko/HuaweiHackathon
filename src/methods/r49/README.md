# R49 CPU / C++14 规则方法

本目录上传三种规则方法及一个对照基线，原样取自本地封存的 `hashjoin_lab/reports/collaboration_20261020/round49_latency_baseline/submissions/`。

| 文件 | 方法 |
| --- | --- |
| `largest_linear.cpp` | 每次扫描候选，选择最大驻留分区释放空间；相同大小按算子、分区编号排序。名称中的 linear 不代表整个回调最坏复杂度为线性。 |
| `best_fit.cpp` | 优先选择足以填补当前空间缺口的最小候选；没有单分区能填补缺口时选择最大候选，必要时继续选择。 |
| `next_guard.cpp` | 若其他候选足以释放所需空间，保护下一条已知 PROBE 所需分区，再按最大分区策略选择。 |
| `official_naive.cpp` | 官方 Naive 策略体仅将类名改为 `MySpillScheduler`，作为对照，不代表新增优化方法。 |

三种规则均排除本次插入/加载的目标分区，周期回调不主动调整。反复扫描选择多个分区时，保守最坏上界为 O((K·P)²)；官方朴素基线使用排序。当前上传不声明哪一种在任意数据上最好。

## 接入方式

**这些文件只有 `MySpillScheduler` 的定义，无 `main`、执行引擎和类型定义，不能单独编译运行。正式参赛仅提交该类文件；以下接入步骤用于本地测试。**

1. 使用官方 2026-10-26 版参考框架提供的 `SystemState`、`Action`、`SpillScheduler` 等类型。
2. 选择一个文件，将其类定义放在框架类型定义之后、使用该类之前，并让框架入口实例化 `MySpillScheduler`。一次只能选一个，同名类不能合并编译。
3. 保持框架的数据结构、动作执行、I/O、Miss 和决策耗时统计语义一致；框架应输出新版五项指标。
4. 仅为本地测试，将该类接入官方兼容框架后按 `g++ -std=c++14 -O2` 构建完整程序；正式参赛仍只提交无 main/engine 的类定义。使用纯 CPU、C++14 标准库，无需 CUDA、第三方推理运行时或外部模型文件。

封存 R49 的构建使用对官方网页提取代码进行空白字符修复后的框架，修复用于可编译性；本目录没有重新发布整套框架。方法文件必须与适用框架一起使用。
