# 更新后数据集的接入约定（2026-10-30）

用户最新范围：不再使用缺少对象热度差异的均匀独立请求做性能选型；主场景转为模拟大数据量/数据倾斜HashJoin，题面限制保持。这个变化是评测目标调整，不是已有AI增益的证据。

## 当前事实

Round8已经提交并推送为`c5c952edb0be0b1d907b12bd37a1751d821267f1`，其综合50例成绩属于旧`final_dataset 2.0.0@33ab5af`。数据监测子agent首次读到远端datasets的`53e7aed05bad46aac4048950d9f8aedef020ef8d`，但manifest和recipe仍未改变，eval/VERSION仍2.0.0；旧eval仍含12条random_uniform。因此不能仅根据分支HEAD前进就声称新数据集已发布。

等待期间，两研发路线仅继续已冻结的倾斜训练诊断。Round9纯路线v2从原8流删除2条uniform，保留6条Zipf/hotspot/lognormal流；旧冻结计划保留。AI原32seed的分层重分析已在范围更新前完成，作为旧目标下证据；后续有限计算统计基准使用6条倾斜流，不再启动uniform性能/学习实验。

## 新版本到达后的执行顺序

1. 数据监测agent确认不可变commit、VERSION、manifest/recipe/生成器SHA及变更范围；只读元数据，不执行求解器、不读新测试成绩。若仅README变化，继续等待真实数据发布。
2. 主agent接管新输入物化和逐行合规审核。区分“manifest声明合法”与“实际输入已核查”；核对K/P/N/M、B、带宽、罚值、操作计数、相位和最终单分区大小等题面限制。下载按用户1GiB确认规则处理，本地生成不冒称下载。
3. 对所有新旧train/dev/eval比较原始输入、去成本头的操作流和按`key % P`规范化的分区流SHA；同seed不同B、大小映射、分布变体按完整底层seed分组，不能把行数当独立环境数。旧eval复用必须标为已曝光，不能因为改版本号就重新称独立测试。
4. 在新train内部冻结开发划分。若做分组交叉验证，明确是同分布族新seed还是整族留出；核对每折的family/seed实际组成。分布族只用于离线划分和诊断，不能进入提交策略的在线特征。
5. 固定两条路线的当前对照：纯`round8/pure/paired_confidence.cpp`、AI`round4/ai_prefetch_budget2048.cpp`。候选先在新train/dev筛选；含AI方法还要与同一确定性骨架及强统计基准比较，不能把纯算法替换收益算成模型收益。
6. 候选和门槛冻结后，对新主测试做一次配对终检。主分按新数据标准定义，不继续沿用旧三成员等权；报告读、写、Miss、CPU及尾部。测试访问记账，后续不得根据同一测试反例调参再称独立泛化。
