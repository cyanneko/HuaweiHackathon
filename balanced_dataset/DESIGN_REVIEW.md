# 两套生成机制审查与合成标准的解释

日期：2026-10-30。来源固定于 `cf14092b6bc8a3bf8cfb65466c44acc81e2cf38a`，文件SHA见manifest。结论来自生成源码、冻结配置、来源审核及本次原字节/输入核查；没有根据算法成绩选样。

## 结论

两套数据作为**明确假设下的合成场景**合理，且互补；不足以代表所有真实数据库或官方隐藏分布。更准确的分组名是“静态分区倾斜”和“动态算子共同活跃”，不能把它们标成严格控制其他变量的“分区有/无关联”实验。

### final_dataset 2.1.0

[生成器](../final_dataset/tools/random_workloads.py)的 `_probe_weights` 给全部K×P分区生成一次固定概率；`construct` 之后独立抽取每次Probe。Zipf随机重排全局排名，hotspot从全部分区随机选热点，lognormal给各分区抽对数正态权重。

- 给定该例概率，近期兄弟分区的偶然计数增加不会改变指定分区的未来真实概率；算子归属没有独立的共享动态生成过程。仍可从长期样本学习固定非均匀热度，不能把IID误解为不可学习。
- “没有额外时间依赖”不等于所有统计量相互独立：每次只选一个分区，固定窗口的计数有总和约束；概率归一化与固定热点数也引入约束。未知概率的统计估计还可能借用先验。这些都不同于dyna中的共同活跃状态。
- Build字节布局与Probe热度分别生成，随机排名分别打乱。大小不直接决定访问热度；但两个分布可共用形状参数，不能把所有跨案例统计量声称完全独立。
- 72个eval覆盖大小、容量压力、成本参数和静态倾斜；全部Build结束后统一Switch，没有跨算子Build/Probe混合，也无热点迁移和算子活跃度突变。15/72例K=1，不能测试算子间共享流量效应。
- 分区大小上限人为设为0.8M，确保每分区可装入；这种裁剪会改变尾部分布。多个大分区不能共存时，性能瓶颈可能是容量而非预测。不能仅凭某家族低分判断其访问分布更难。

### dyna_dataset 1.0.0

[生成器](../dyna_dataset/source/generator.cpp)先用动态算子概率p抽算子，再用该算子的q抽分区；p按全局操作更新，q仅在本算子的INSERT/PROBE后更新。

- 普通q以1/P为目标，归一前约束在target的[.95,1.05]内，因此归一后在约 `[.9048,1.1053]/P` 内。p显著变化时，同算子普通分区的全局访问概率p×q大致共同升降，确实体现前述共同活跃机制。
- 这也给分层模型很强的先验便利：把算子流量近似均分到普通分区已经很接近生成模型。收益可能来自减小估计方差或利用近均匀先验，不能只归因于学会预测“冷分区即将变热”。
- 12例中只有两个持久热分区、一个持久冷分区异常；它们全程保持目标，没有新增/消失的局部热点，也没有强烈的算子内热点轮换。真正“算子很热但某分区长期很冷”的覆盖有限。
- INSERT与PROBE使用同一缓变q过程，持续异常同时影响两侧；final则分别生成两侧布局。二者还存在Build/Probe分布关系的混杂。
- 每例5M操作，算子slow/fast/burst各4例；shared/staggered各6例。无次数配额、没有为满足目标计数而强制单算子尾部，独立随机流和完整审核是合理设计。shared是共同阶段阈值而非屏障，staggered覆盖混合阶段。
- 所有算子始终参与抽样直到EOF，没有真实查询结束后的退出机制；所有12例固定W=100、R=80、miss_penalty=100。不能据此验证所有生命周期、介质和罚值下的稳健性。当前部分策略恰用100μs代理，尤其应保留静态侧的广泛成本参数。
- 12个seed仍只有12条独立生成流；6000万请求不能作为6000万个独立实验样本。相同base seed的R71/R72及缩短变体不能跨训练/测试当作独立样本。

## 当前两套来源的主要混杂

| 属性 | final完整72例 | dyna完整12例 |
| --- | --- | --- |
| 每例操作数 | 65,614–1,048,576，中位207,771.5 | 固定5,000,000 |
| 实际总Build字节/M | 约1.15–3.96 | 约1.49–12.00 |
| 算子内普通热度 | 可强烈且固定倾斜 | 近均匀、小幅缓变 |
| 算子流量 | 固定分区概率之和 | 明显动态变化 |
| Build/Probe交错 | 无 | 6个staggered案例有 |
| 读写带宽与罚值 | 跨例变化 | 固定100/80/100 |
| 原用途 | eval72，部分多次曝光 | train6/dev3/holdout3，已有全12比较 |

以上差异不能靠从72抽12自动消除；原静态集合没有5M案例，无法仅选样实现长度匹配。为保持原字节，本次没有补长或截断。等案例数解决评分权重，不能解决因果归因。

## 为什么仍采用24例回归标准

用户目标是两种分布等权覆盖，24例可直接复用现有逐例均分评测器，且比每次完整72＋12更省静态侧评测次数。分层抽样覆盖三家族与长度范围，避免按得分挑样本；原始全量集合保留，新增独立suite身份。

必须读两个分组和逐例退化，避免一侧收益抵消另一侧严重失败。静态子集中K=1/2/4/8分别4/4/2/2例，动态则偏K=8；这进一步说明本集是覆盖标准，不是匹配参数的相关性实验。冻结后不因看到此差异重新挑选更有利案例。

后续若要证明“使用算子信息的收益来自共同活跃”，应另做配对机制对照：固定大小、N、K/P、带宽、罚值和阶段顺序，交叉控制算子活跃度是否变化与算子内组成是否变化，再比较相同规划器的分层/平坦估计。所有变体按base seed整体划分，不能把配对流拆进训练和评测。本次没有生成这些新实验数据，也没有把该建议当作已验证结果。
