## 已核对一致的内容

- 初始 BUILD、空分区驻留；Hit 只指分区驻留，不指 key 匹配；PROBE 不增数据。
- 磁盘态 INSERT 只写新增字节，后续 LOAD 读完整 data_size；LOAD 后再 SPILL 全量付费。
- overflow 看插入前状态；miss_count 在 miss 回调前增加；miss 不再补记 Hit；periodic 看当前操作及先前动作完成后的状态。
- 全局 INSERT/PROBE 计数，每 B 次回调，SWITCH 不计数、不重置；末次符合条件仍回调，不自动释放算子。
- next_op 指当前输入的紧邻下一行；同一操作多个回调重复展示，不能当成多次访问。
- 动作顺序执行，空分区 SPILL 不改变状态，LOAD 逐步检查内存。
- 精确 overflow 缺口 max(0, memory_used + tuple_size - M)。
- 纠正后的对比：Build 落盘 p1；Probe 0 Hit，Probe 1 换出 p2/加载 p1，Probe 2 换出 p1/加载 p2，Probe 3 Hit。Hit=2、Miss=2，写 384 字节、读 256 字节，I/O=3.84+3.20=7.04μs，加 miss 惩罚为27.04μs，另加决策时间。

## 必须处理的问题

### 1. 样例输入含跨页空行，直接复制会漏执行三次 Probe

位置：STATEMENT_ENHANCED.md:319–325。PROBE 0 0 后有三行空行。N=11，但操作区实际14个物理行，其中11行非空。参考 main 严格 getline N 次，不跳过空行，因此读到6次INSERT、1次SWITCH、1次PROBE、3行空行；剩下的PROBE 0 1/2/3完全不执行。按参考 Naive 静态推演，实际为Hit=0、Miss=1、I/O=4.16μs，无法得到展示的样例输出。

来源：原始 Markdown 的 PDF 跨页提取遗留，补充版将其包入可复制 text 代码块时未清理。建议仅清理补充版样例中的空行，保留冻结原件；声明操作区N行均为有效操作，不含空行。无需修改参考引擎。

### 2. 输入兼容说明插进正文中间

位置：253–256行。当前形成“熟悉输入> 【解释补充……”和后续孤立的“输出格式、验证”。这不是独立引用块，切断了原句。建议恢复完整正文，再把补充放在算子头定义之后的独立段落。

### 3. 当前 INSERT 目标保护：规则与引擎仍矛盾

位置：111–132行、接口代码注释。补充正确指出 executeActions 没有目标拦截，但原文仍多次宣称“引擎会静默忽略”。参考实现实际上会执行该 SPILL，然后沿已经进入的驻留插入分支增加 memory_used，造成状态不一致；不能把此动作视作安全无效动作。

建议在每处相关规则附近明确：禁止动作由调度器主动排除；“引擎静默忽略”为原文描述，与保存代码不一致，不能依赖。该保护针对overflow返回列表；当前INSERT完成后的periodic可以合法SPILL刚写入的分区。不要扩大成整个操作期间都禁止该分区落盘。

### 4. 释放量纠正没有覆盖提交骨架附近

位置：132行对照743行。前文精确公式正确，骨架仍写“须释放至少 tuple_size 字节”，会误导按骨架实现者过量落盘。例如M=100、used=90、tuple=20，只缺10，不是20。

建议保留原代码时，在骨架前紧邻标注该注释不精确，以缺口公式为准；表格写“仅当目标驻留且本次插入将超限时”触发overflow，避免把磁盘态INSERT误解为也触发。

## 仍应澄清的表述

### 5. 计时冲突虽解释过，后文仍重复错误概括

位置：233–246、301–302、807–811行。补充对参考代码的判断正确：high_resolution_clock测经过时间，不是专用CPU时间；getSystemState()构造、operators深拷贝及该临时状态销毁位于被计时lambda内。不能同时无条件称“框架自身耗时不计入”。动作执行、输入解析确实不在Total_Decision_Time中，但占真实进程时间。

建议把计时解释链接或提示放到输出字段、实现指引的重复位置；明确模拟I/O是数值成本，并未sleep。60秒外部超时起止边界由评测器实施，参考main本身不实现超时；不把本地进程计时的具体边界说成已由官方代码证明。

### 6. miss最后LOAD目标：明确规范，但引擎没有检查末项

位置：151–157行及processProbe。文字要求末项LOAD目标；引擎只检查执行全部动作后目标仍驻留，不检查动作类型集合或最后一项。补充应说明这是需主动满足的文字约束，与目标保护采用同一解释原则。空间已足够时允许只返回LOAD目标，不必先SPILL。

### 7. “所有落盘与加载I/O之和”漏写磁盘追加

位置：230、300行。参考processInsert还累计磁盘态分区新增元组的size/W及size字节，虽然前文介绍过追加写，成本总定义仍容易漏算。

建议统一写：Total_IO_Time为SPILL全量写、LOAD全量读、磁盘态INSERT增量写的耗时总和；total_io_bytes同样累计这三者，不只累计显式Action。

### 8. 输出四舍五入与公式的精确性

位置：293–305、printResult。实现用未舍入内部double算Total_Score，再将各项分别保留两位小数输出。因此显示的IO+惩罚+显示的Decision未必恰好等于显示的Score，可能差0.01。比如内部IO=1.004、Decision=0.004，显示分项1.00/0.00，但两项之和内部1.008显示1.01。

建议注明公式作用于未舍入值，展示分项允许舍入差；样例Decision=0.50仅示意，不是精确输出断言。

### 9. 算子头顺序必须标为实现兼容前提

位置：253行。当前用命令语气写“按升序且唯一”，容易被当成官方输入新增约束。原题只给ID范围；参考addOperator按输入顺序push_back，其余按ID索引，未做映射。

建议写“为兼容保存参考实现，本地构造输入按0..K-1排列且不重复；原题未明确保证行序，官方实际输入行序尚未确认”。它不是已经由样例证明的普遍保证。

### 10. 正式范围与样例例外的依据要分清

位置：253、286、861行。原文称样例仅演示格式，但未逐字声明“M最小值在样例豁免”；将256字节样例视为演示例外合理，应表述为本补充采用的解释。另原文要求“部分分区远大于其他分区”，样例最终三个分区均128字节；该例也不能用于推断正式测试必有或必无倾斜。

build_count/probe_count无下界，SWITCH恰好一次未完整形式化，PROBE key范围没有像INSERT一样单独明确写出。解析器不校验这些，不能据此扩展合法输入集合。建议分别保留未明确项，并写本地生成约定，避免把未知都归作畸形输入。MB/GB、隐藏分布、线程/编译器与人工评分等现有末节边界说明可保留。
