# final_dataset 3.0.0：每个算子内部均有分区访问热度倾斜

**540条训练＋72条测试，全部612条通过严格分区热度审核。** 本版针对每个`(op_id, partition_id)`分别赋予正的、不同的目标PROBE概率，并逐算子审核内部冷热差异。每个测试点都满足本合同；训练集也采用同一合同。全部为普通随机负载，无特殊corner样本。

## 题面和旧版的结论

[保存的原题](https://github.com/cyanneko/HuaweiHackathon/blob/11b719b/docs/statement-2026-10-20/statement.md#L381)写的是“部分分区远大于其他分区”，明确要求的是分区**构建字节量**倾斜；它没有承诺PROBE访问概率两两不同。本版同时审核构建大小和访问热度，后者来自本轮用户要求，量化阈值是数据工程验收条件，不是官方隐藏分布保证。

旧2.1.0生成器是给全部`K×P`分区赋权重，再抽全局分区；它不是只给算子分配不同热度。但是热点家族只有热、冷两档，组内等概率。72个旧eval中的28个热点样本因此不满足全分区概率互异；其中3例还包含5个算子内部近均匀的实际分布。

明确反例是旧`eval_026_random_hotspot`：4算子×8分区只有2个全局热点，至少2算子内部理论上均匀。独立重读原始输入后，算子2的PROBE次数是`[270,259,268,254,268,252,258,250]`。旧版完整元数据审查及这份raw反例见`reports/parent_skew_audit.json`；120个旧复用训练的sidecar没有分区计数，报告没有把它们冒称为已逐行复查。

## 本版逐点合同

令`a[o]`为算子总访问质量，`b[o,p]`为算子内部条件概率，联合分区概率为`a[o]×b[o,p]`。两层分解不影响分区粒度，关键是每个算子的`b[o,p]`本身必须不同且明显非均匀。

- 全部`K×P`个联合目标概率为正、两两不同，和为1；每算子内部条件概率也两两不同。
- 每个算子目标分布相对均匀分布的TV距离至少0.20，目标最高/最低概率至少2倍；不会仅靠微小扰动制造名义上的差异。
- 每个算子概率质量至少`0.5/K`，避免仅让少数热门算子承担全部访问。
- 真实输入逐行复算后，每个算子实际条件频率的TV距离至少0.10，且至少访问2个分区。
- 每个分区构建字节量为正且不超过M；另查真实大小差异，保留父BUILD布局。全包最低大小比为1.748106，不把热度的2倍门槛误用到字节大小。字节量与热度分别验证；题面没有给大小倾斜的量化阈值。

TV定义为`0.5×sum(|b[p]−1/P|)`。本版最低目标TV为**0.215000**，最低实测TV为**0.209064**；这两个最小值均遍历了全部612例中的全部算子。

有限随机采样中，实际次数可能巧合相等，也可能尚未访问极冷分区；这不表示其目标概率相等或为零。本版不强迫全部实际计数互异，不把均匀采样的小幅计数抖动当作热度倾斜。sidecar同时保存完整`probability_certificate`和`probe_counts`，可分别核对概率与观测。

## 普通随机场景与数量

| 家族 | 训练 | 测试 | 本版生成方式 |
|---|---:|---:|---|
| random_zipf | 216 | 28 | 每算子内部独立打乱分区排名，再按局部Zipf权重采样 |
| random_hotspot | 216 | 28 | 每算子至少有热、冷各一分区，组内连续权重各异，不再均分 |
| random_lognormal | 108 | 16 | 每算子各分区独立抽取连续权重，必要时确定性增强对比 |

概率固定后，PROBE按联合分布IID抽样；不预测单次随机请求。只在目标权重不够倾斜时提升对比，增强指数、冷热组质量及浮点去重幅度均写入证书；不重抽seed，不按算法得分筛选，不丢弃失败样本。

沿用2.1.0推荐540训练和全部72测试的K/P/内存/成本/规模与BUILD配方，保留父分区大小SHA核对，重建PROBE分布。训练和测试各自的父来源保持不变，未将旧eval转成训练。所有输入都是新PROBE流，已在raw、操作流、分区语义三个层面检查612例内部及相对父843例无重复。

| 项目 | 训练 | 测试 |
|---|---:|---:|
| 输入条数 | 540 | 72 |
| 总操作数 | 78,112,569 | 22,528,629 |
| 单例最小操作数 | 33,493 | 65,614 |
| 单例最大操作数 | 1,048,576 | 1,048,576 |
| 原始输入字节 | 1,661,641,259 | 474,874,682 |

全部真实INSERT随机交错，所有算子SWITCH后进入随机PROBE。仍不模拟BUILD/PROBE重叠或动态热点迁移；没有5,000,000操作上限样本，也没有人为控制大小与热度的相关方向。这些限制继续明确保留。

## 使用、审核和复现

Python3.10+，仅标准库。从包所在仓库根目录运行：

```sh
python -B final_dataset/tools/verify.py --package final_dataset --report final-v3-audit.json
python -B -m unittest discover -s final_dataset/tools -p 'test_strict_weights.py' -v
```

验证器独立逐行读取输入，不导入生成器。审核题面范围、阶段、头部计数、容量、大小倾斜、目标/实测热度、来源与工具指纹、完整文件集合及跨集去重。`reports/validation.json`保存本次全部612例审核结果。审核不运行调度算法，不代表动作轨迹或算法得分验证。

从零复现时，另建空目录，先复制`recipe.json`、`VERSION`、`eval/VERSION`及`tools/`，再执行：

```sh
python -B NEW_PACKAGE/tools/generate.py --package NEW_PACKAGE --jobs 2
python -B NEW_PACKAGE/tools/verify.py --package NEW_PACKAGE --report regenerated-audit.json
```

`--resume`只接受完整且哈希、配方、seed和倾斜合同仍一致的txt/meta成对文件；中断留下单文件时安全停止，不能自动覆盖恢复。原配方、输入和生成源码均冻结，不在原件上调参。完整复现还应保留`provenance/`和本说明。

## 版本边界

2.1.0全量原件保留在Git提交`c65c7b32b06a5764ce9ad4881133a3c6eb33ed17`；其中770训练的旧均匀及辅助样本没有混入本版540条严格训练。旧corner/dyna/balanced集合及各自冻结来源不在本版修改范围内。

3.0.0更换了全部PROBE流并增强每算子内部倾斜，旧2.1.0或旧50例算法成绩不适用于本版。父规格与原测试已公开，因此本版不声称独立盲测；本次只构建和验证数据，没有训练模型或运行候选算法，也不以新旧集平均分差异宣称算法提升。概率证书和未来操作统计仅供离线审核，不能提供给在线调度器。
