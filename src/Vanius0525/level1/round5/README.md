## 数据是否分训练/测试

有整条输入流划分：[审计](SPLIT_AUDIT.json)覆盖原始 train 96、val 32、历史 holdout 64、历史 OOD 64。跨这四批未发现字节重复、按 `key % P` 归一后的相同输入或仅隐藏罚值变化的相同动态过程。[检测验证](SPLIT_CHECKS.json)确认能识别复制、键重命名和罚值变体。`train.py` 新增拟合前的强制 train/val 检查。

**这不等于没有过拟合。** 验证集参与调参，785例三成员套件参与策略选择，fresh/OOD历史批次也已查看，因此均为开发/回归数据；没有拟合模型权重的测试，也会被人工选策略过拟合。原始 train/val 共享生成器机制，换 seed 不能独立证明分布外泛化。

续接后的[扩展审计](EXTENDED_SPLIT_AUDIT.json)进一步覆盖原train96＋context fresh96＋context OOD96、val32及三成员209/48/528，共1105流；三个层次的跨集合重复均为0。这检查了当前这些输入，不是全部历史训练缓存/模型来源的一致性审计。两个训练扩充批次在审计中单独命名，以便同时发现训练来源间的重复。

新测试设计预先固定为两个机制：多次反转“大/小对象热集”，以及37/113等非二次幂停留长度与方向反转；16流共享8组生成 seed，成对关联必须保留。`generate_mechanism_test.py` 在训练完成和源码冻结后才生成；先查与train/val重复再测，不参与拟合/阈值选择。它仍是合成机制诊断，首次查看结果后即记为已曝光，后续不能继续称盲测。真实比赛隐藏分布没有证据可确认。

## AI 是否以离线最优作 ground truth

ground truth 是训练参考真值。现有方法并没有使用全局离线最优：

| 方法 | 实际标签 | 限制 |
|---|---|---|
| 原 `train.py` | `1/(1+next_probe_distance/32)`，永不再访问为0 | 复用距离代理，未直接优化完整读写、Miss罚和CPU |
| round4 context | 换当前动作，再固定pure续接4096步 | 有限窗口/固定续接的条件成本，存在截断及动作表示偏差 |
| round4 lazy | 前缀状态选择配置，再固定配置至完整流结束 | 配置池内反事实成本，不是全局最优策略 |
| 本轮 `train_interval.py` | 配置保持256个合法可见观测；再分别以0/2两配置续接完整后缀；学习两教师下较保守的截断相对收益 | 不含CPU标签；pure采样轨迹会偏移；末尾区间可能较短；完整后缀也不等于OPT |

真正离线最优在小状态下适合做上界诊断、候选池检查或教师；离线标注可以看未来和真实罚值，部署特征不能。离线最优的动作依赖在线不可见的信息，相同合法特征可能对应相反动作，不能要求模型确定性复现全部标签。异大小、付费写出、BUILD增长及Miss罚也使简单Belady最远未来规则不等于本题OPT。可扩展近似教师必须按实际求解范围命名；不能把heuristic rollout写成ground truth最优解。

标签更精确还不够：需要检查候选池是否包含好动作、两个续接器的排名是否一致、实际策略产生的新状态是否可泛化，以及CPU开销是否抵消物理收益。本轮记录续接排名冲突，按输入流等权训练深度3小树，收益不足0.05分则使用默认配置；这个门槛预先固定，不能根据新测试再调。

## 本轮实现与对照

- `pure_cover_singletons.cpp`：保留Best评分和top4集合，同时比较所有能单独覆盖缺口的分区。只改变候选召回，不混入新热度/写量参数。
- `ai_refresh256.cpp` / `ai_refresh1024.cpp`：相同旧树和共享合法历史，只改选择频率；旧前缀教师与重复选择不匹配，仅作诊断。
- 面板的 `ai_callback` 是旧 `ai_gate_d3_m02.cpp`，其树与标签均不同，只作既有方法参照；频率效应只能先从相同旧树的 `ai_prefix`/`ai_refresh256`/`ai_refresh1024` 三列判断，不能把这一旧callback列与它们的差异归因调用频率。后续若需要每回调的严格消融，应另生成完全相同树/14维特征的callback版本再测。
- `train_interval.py`：均匀reservoir（对符合条件的回调等概率抽样）每流最多12状态；只用原train96，流内权重和为1。两种完整后缀续接、配置收益标签、CPU留待部署实测。输出 `ai_interval256_d3.cpp` 后才进入正式对照。
- `campaign.py`：开发验证→区间训练→新模型开发验证→三成员完整对照→冻结后机制测试；完整报告才跳过，遇部分报告停止恢复，不覆盖原始数据，不自动晋升。

每例3次成对交错计时，独立动作重放；成员各自逐题均分再三成员等权，不将不同批次混成一张榜。预先规定晋升至少要求：所有合法性检查通过，完整三成员主分相对本批Best改善、物理成本最坏倍率不比本批Best高5%以上、新机制测试无未解释灾难退化，最大规模检查完成。小改进仍需额外重复确认；未满足全部条件就保留Best。
