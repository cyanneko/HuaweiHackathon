# R73：不可见 miss 罚值的先验敏感性

## 修改

`MySpillScheduler.cpp` 是隔离的 VanBest 候选，原 `reuse*(1/R+1/W+1/size)` 改成 `reuse*(1/R+1/W+prior/size)`，`prior=sqrt(1000)=31.6227766 us`。真实罚值没有传入调度器。该常量是公开范围 `[1,1000]` 的几何中心，不是对当前用例真实罚值的估计，更没有调度最优保证。

公开接口没有真实罚值；两份操作流及所有可见状态完全相同、仅隐藏罚值不同的输入，对合法确定性策略不可区分。不能用 miss 次数或 IO 字节反推出一个独立的隐藏计分参数。若要对不同罚值更鲁棒，只能改先验/优化跨罚值风险，或由官方修改接口。

保留原版和 31.62、100、500.5 四个先验，所有源码及编译身份见 `build_manifest.json`。原冻结 VanBest/AI 与 R72 数据、结果未修改。

## 试验边界

- 24 个新合成操作流，每个 20034 操作；前 16 个为参数选择诊断，后 8 个为不同种子/尺度检查。覆盖均匀、小热点、大热点、Zipf、算子转移热点、单点转移、热点尺寸切换、循环扫描。
- 加上 R72 的 9 个 train/dev **160008 操作 smoke**，不是 500 万操作正式用例。未读取 R72 holdout。
- 每条确定的物理轨迹以真实罚值网格 1/10/100/1000 重新计 IO＋penalty×miss。这四点是敏感性视图，不是四个独立数据集。
- VanBest 四先验共 132 次运行；4 条合成流×4 先验另跑隐藏罚值 1000，对比隐藏罚值 1 时 IO/hit/miss 完全一致（16 项）。这与源码依赖检查一起支持不可见罚值未被读取，不宣称仅凭三个汇总指标证明每个动作相同。
- AI 两版本另跑 66 次，见 `ai_check/`。原始输出保留。
- 本轮上传/编译可能并行，所有表仅比较模拟物理 IO＋miss，不用本轮 D 判断快慢。

31.62 是偏稳健的候选：相对较大先验牺牲少许合成均值，限制该选择集的最坏退化。这是数据相关取舍，不能推广为任意分布稳健保证。R72 smoke基本不受影响且有小幅负收益，因此**不自动替换原版默认**。后续与 R74 refault 方法分别归因，必要时再测组合。
