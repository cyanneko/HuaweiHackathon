## 与当前原算法、联合版的实质差异

指定文件首行是 `R80_MODE=2`。其 `release` 只运行一个由分层next概率驱动的proposal，随后返回；`comparePlans` 和 `chooseAlternative` 虽仍在类体中，本模式不调用。不能把它解释为在当前联合版上追加一项算子热度。

| 机制 | 原 paired100 / risk_pool100 | R80_next_hier_fast100 |
|---|---|---|
| 常规PROBE估值 | 两个既有集合；风险联合版仅替换最终集合差值的未来均值 | 直接以分层next概率生成唯一集合 |
| 算子信息 | 联合版用同算子其他分区的在盘事件/暴露校准 | 对原始next频次按算子自适应收缩，保留算子样本质量 |
| 混合阶段 | paired比较须所有算子PROBE；联合风险核也须全PROBE | 已处于PROBE的算子在混合阶段即可使用分层概率 |
| next衰减 | 半衰期2048，每至少256个PROBE时钟步整体缩放 | 同半衰期、按时间戳惰性精确衰减；查表减少常用指数开销 |
| 取概率 | 当前联合核线性汇总及扫描 | 每次release刷新算子汇总，只按需查询实际候选分区并缓存 |

R80分层概率为 `((1-alpha)*c_i + alpha*S_op/P + 64/n)/(S+64)`，其中 `alpha=.75/(1+strength)`，strength由算子内计数异质性及有限样本修正产生。它保持同算子总样本质量；算子内差异越大，共享越弱。全局分区概率原本已含算子访问份额，因此这里是收缩，不是两份频次直接相加。分层前提是否适合强Zipf仍需训练数据验证。

`sampleNext` 只使用合法next并按全局PROBE序号去重，不把当前Miss直接加入这套频率。普通Hit身份仍不可见。当前Miss用于另外保留的refault统计；在mode2普通PROBE路径中，候选估值直接采用hier概率，不能将此收益全部归于refault。扫描/循环与BUILD的其他路径仍可能读取旧refault逻辑。

## 大小已经参与费用

设候选的访问次数代理为 `reuse=64*p_hier`。源码395–417行的排序密度是：

`reuse * (1/R + 1/W + 100/s)`。

top4子集的损失再乘分区字节并加写项，等价于：

`reuse * (s/R + s/W + 100) + 0.25*s/W`。

所以R80和当前paired骨架都已经结合访问与大小；不是只有次数。原始Miss计数与字节直接加权相加还会混合不同单位，Miss计数又依赖当前驻留策略。更清楚的实验是明确一个有单位的成本近似，再控制只变其中一项。

原作者R80报告列出的受控因素为罚值代理、flat/hier估计、是否paired，以及按需缓存。未发现把额外即时写权重0.25改为1的独立消融；当前仅能说该系数沿用启发式，不能说已有最优性依据。

源码保留 `R74_SIZE` 分支 `sqrt(1+s/typical)`，但指定版本宏为0，实际不执行。已核R74原发布说明：大小保护在六个500万操作开发例仍优于原VanBest，但其总成本倍率均值0.912844弱于operator的0.902130及coverage的0.902889；另有synthetic_09按同轨迹罚值1000重评分的物理成本为基线1.994013倍。因此不能默认启用该大小因子；这也不直接否定当前拟议的R80对象总价值排序，因为底层估计器、代理和改动均不同。

## BUILD / PROBE 语义

阶段是算子级，不是同一算子内各分区各自切换。不同算子可以一个BUILD、另一个PROBE，并竞争同一内存。BUILD在盘追加只收写成本，不增Probe Miss计数；BUILD分区不能LOAD。

R80在混合阶段，对BUILD候选走旧分支。该算子尚无合法PROBE历史，也不会记录BUILD驱逐refault episode，正常情况下其reuse为0，因此没有凭空加100微秒Miss代理；即时写仍有0.25*s/W。已PROBE候选用hier。不能把“删除BUILD的Miss罚值”说成必然改变这个实现：先证明确实存在非零项，否则消融只是无动作差异。

进一步修改BUILD保留偏好仍须算机会成本：一个最终会在BUILD落盘的分区，首次写与后续追加之和等于最终字节；早晚落盘未必改变其累计BUILD写量，却会改变内存占用和Probe初始驻留。此处没有提出新的未来长度估计或权限外信息。
