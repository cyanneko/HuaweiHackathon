# R82：驱逐组合搜索与立即写盘权重

本轮继续开发非网络方法，父版本固定为 R80 共享概率按需版。两项改动各自从同一个父版本派生，不混入 R81 的快速算子热度，以区分收益来源。官方框架和输入可见性不变，仍使用 Linux C++14/O2。

## 两个候选

**R82_singlefit025：增加全体驻留分区中的单分区候选。** 原方案只对热度评分最低的四个分区枚举15个子集，可能遗漏排名之外、单独就足以腾出空间且总代价更小的分区。新方案在原候选遍历时缓存已经计算的损失，并寻找这样的单分区；原方案照常只运行一次，裁剪多余驱逐后，才与新增候选比较。只在估计损失严格更小时替换，平局保留原方案，不重算风险、不为未执行方案记账。

采用原损失尺度 `L(A)=sum(priority_i*bytes_i + .25*bytes_i/write_bandwidth)`。候选必须驻留、非空、足够腾出本次缺口，且不是当前加载目标或已知 next 目标。特别保留“前四个不足，但原贪心组合比任何单分区便宜”的情况，不能只因发现一个够大的分区就采用它。

**R82_write1：提高原子集选择中立即写盘的权重。** 不扩大候选范围，保持前四个及原回退流程，仅将普通 Probe 子集损失中的 `.25*bytes/write_bandwidth` 改为 `1*bytes/write_bandwidth`。实际框架每次写盘确实计入完整的 `bytes/write_bandwidth`；但原 `.25` 可能是与未来代价代理配合的经验校准，不能断言改成1一定更好。

两项增强都只用于全部算子已处于 PROBE，且未进入扫描或循环保护的普通路径。BUILD、混合阶段和这些保护路径保持原行为；概率、100us罚值代理、预测窗口都不变。新增数组复用，首次分配及全部额外工作均计入 D。
