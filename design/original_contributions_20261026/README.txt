最终说明：../topic20_original_contributions_20261026.pdf（10页）

本轮贡献：
1. 周期回调提前落盘下一INSERT目标，利用溢出回调与周期回调的可行动作差异。
   推导下一INSERT即时写费优势，构造同前缀正反例。裸用出现约一万倍退化，不能默认启用。
2. 为BUILD增长到M及首次读回建立保守暴露预算；风险额度来自已有可见成本下界。
   只证明声明的阶段成本暴露约束，不是Score相对BASE的5%竞争比。
3. 用有方向的跨算子SPILL来源账本追踪谁挤掉谁；消融尚未证明净收益，非默认模块。
4. 构造不同命中历史却相同回调观察的输入；提出兼容历史的稳健经验损失公式。
   数学原型完成6400组穷举；未宣称实现完整在线不确定性优化器。

文件：
BudgetedScheduler.cpp：单文件C++14候选；默认flags=4959；无参数构造MySpillScheduler。
OriginalScheduler.cpp：保留原型和反例；默认含裸提前落盘，仅用于研究，不建议直接部署。
二者类名相同，只能选择一个文件编译。没有修改根目录原有两个提交版本。

配置位：1提前执行同计划Build落盘；2必淘汰预取；4事件/窗口适应；8跨算子软配额；
16线性快速计划；32旧开发树首次miss路由（默认关闭）；64排除不可共存读回的策略惩罚；
128禁止自动切入近期性（默认关闭）；256保留有效规则；512提前落盘下一INSERT目标；
1024方向干扰账本（默认关闭）；2048放宽其他算子均为PROBE的门槛（默认关闭）；
4096不可逆增长和首次读回的5%风险暴露预算。
基础控制器351；裸提前863；仅方向账本1375；组合1887；预算版4959；预算+账本5983。

实验分离：
初版先冻结，再生成610例，含20类分布、128端点、跨算子/CPU场景与正反分支。
预算版是在观察这批反例后提出；相同610例的预算成绩只能叫回归。
预算版再次冻结后生成32个新针对性输入，验证有已有成本时的开关与相反后续。
所有公开引擎成绩包含真实决策耗时，重复3次。三组500万操作是历史规模回归，各配置1次。
严格审计程序添加了观察摘要，不能使用它的时间作为正式Score；正式时间来自未改的公开引擎。

主要结论：
预算版在610例中关闭了全部危险目标提前落盘，I/O和miss与基础控制器相同；细微Score差异来自CPU计时。
新32例中机制有实际开启，但没有稳定超过基础控制器。不能宣布性能全面领先。
方向账本的几何均值变化很小，单组公式均值和CPU开销没有同步改善，不默认启用。
创新性主张是具体机制、局部命题、风险约束与信息边界，不是对全球首次或官方评分的保证。
