## 现象、长短板与小技巧

1. 题目目标是逐例截断分再求和封顶；总I/O、平均成本比、平均逐例分可能排序不同。多套合成集都封顶50，不能据此宣称隐藏集满分。表中“诊断均分”仅以I/O+Miss成本计算，排除了决策时间，不能替代正式口径。
2. 可见Probe序号由hit+miss构成；回调重复展示同一操作需要去重。没有普通Hit回调，历史频次与stride均是受限证据，不能使用完整访问流作为线上特征。
3. 新BUILD未来增长与最近复用距离是不同问题。学习模型可能偏爱旧大分区、写出新小BUILD；磁盘追加和未来完整载入会改变长期成本。阶段保护有可解释修复，也会误伤别的分布。
4. 网络在BUILD不是总无用：它也能选出更合适的小旧PROBE。保护候选必须同时覆盖启发式短名单生成与网络重排，否则仍可能在另一层被选中。
5. 冷启动退回最大规模策略；真正需要多个受害者时再使用堆。推理预算与快速路径比增加模型容量更有直接成本意义。
6. 预取影响状态，也影响未来观测机会。已在HANDOFF的Open Ideas记录独立研究问题；赛题反例成立，现实适用性与新颖性尚无证明。
7. 零I/O案例可能被微秒级计时噪声主导。串行配对、交错次序、重复计时、独立动作审核各解决不同问题，不能用一次墙时归因算法机制。
8. 同学数据只读取manifest和输入，未阅读其算法。528例有524个声明的operation group，不能把所有样例当独立采样；已曝光数据也不能再称盲测。

## 2026-10-30：固定 penalty 代理决定采用 100 μs

**决定：在用户给出的 100 与 500 两个选项中，选择 `penalty_proxy_us = 100.0`，作为后续实现采用的固定 miss 代价代理。** 用户明确更倾向100；该选择结合下述模型与历史证据，是工程取舍，不是已证明的最优常数。500不作为本次默认，只保留为均匀先验下的理论对照。此次授权是记录思考与决定，未修改调度器、框架、训练或评测配置，也未运行新性能实验。

### 问题来源：策略不知道真实罚值，评分仍然准确

题面输入给出 `1 <= miss_penalty <= 1000`（μs）。main读取它并传给引擎，保存在私有 `miss_penalty_`；`SystemState` 和三个回调参数不提供该字段。当前两份发布源码的代价估计使用1μs下界，不能由此推断实际罚值就是1。官方框架始终计算：

```text
Total_Score = Total_IO_Time + 输入真实miss_penalty * Miss_Count + Total_Decision_Time
```

代理偏低可能影响动作优劣，不会把评分罚值替换成1。本轮前置核查读取了 [round8/FINAL50_RESULTS.json](round8/FINAL50_RESULTS.json) 的50份对应输入首行和全部600条计时记录：记录罚值全部与输入一致，逐条公式检查通过，最大显示舍入差0.01μs。该结果只确认这批记录的罚值和计分，没有重跑solver，也不把已曝光eval的罚值分布拿来拟合新常数。

### 现实系统证据：只能参照量级，不能反推题目分布

题目已经独立收取 `bytes/W`、`bytes/R` 和回调经过时间。真实系统中映射到penalty的应是模型尚未计入的附加成本，不能把完整读取延迟或已计入的CPU成本重复相加。题面没有给出隐藏罚值的概率分布，SSD容量也不足以确定该分布。

### 为什么均匀假设推出500.5，却不能直接决定比赛最优常数

明确假设：真实罚值 `p` 从整数1..1000均匀抽样，且与工作负载及其他可见信息独立。对固定策略θ，记 `Aθ = IOθ + Dθ`、`mθ = Missθ`；真实p不影响状态转移且策略不可见，因此：

```text
Cθ(p) = Aθ + p*mθ
E[Cθ] = Aθ + 500.5*mθ
```

所以，**若接受该独立均匀先验且优化期望原始成本，500.5有严格目标等价依据，100不是该先验的均值解。** 不能因为最终选100就改写这一结论；把启发式常数替换为500.5也不等于得到最优策略，因为热度、候选集合和未来代价仍是近似。

比赛逐例分还要除以Naive成本。固定工作负载下写 `B(p)=A0+p*m0>0`，暂不考虑clamp和套件封顶，有：

```text
E[Cθ(p)/B(p)] = Aθ*E[1/B(p)] + mθ*E[p/B(p)]
p_eff = E[p/B(p)] / E[1/B(p)]
```

这个权重由Naive的I/O、决策开销和Miss数决定，不只由区间决定。整数均匀逐点计算：`A0/m0` 为100、1000、10000μs时，`p_eff` 分别为317.823、443.215、492.559μs。clamp使候选之间的有效区间不同，官方套件封顶还耦合多个案例，因此这些数不是完整比赛目标的通用最优代理。**该推导也不支持宣称100在均匀先验下最优。**

### 在100与500之间选择100的具体依据和风险

1. 官方均匀先验没有被证实，当前目标又是逐例归一化得分；不把500.5的条件性原始成本推导当作必须选500的理由。
2. 当前复用概率来自稀疏、受策略影响的观测。100将miss权重从下界1提高，同时相较500降低了对这项不确定未来代价的放大。选择意图是避免仅凭不可靠热度估计为减少一次预期Miss付出过多实际写盘；这只是机制判断，不保证整体I/O、miss或尾部单调改善。
3. 旧罚值实验说明增加代理并非所有目标同时变好，支持把它当独立策略参数管理；不将邻近64的结果外推为100的性能证明。结合用户明确偏好，在两项尚无直接胜负证据的选项中最终选100。
4. 风险保留：真实p偏高且热度预测准确时，100可能低估减少Miss的收益，500可能更好；真实p偏低时，100也可能高估其代价。当前没有100相对500或旧1的有效提升结论。

### 决定如何进入后续实现和验证

- 本次冻结的是**参数决定100μs**。当前发布入口仍为 [round8/CURRENT_BEST.json](round8/CURRENT_BEST.json) 的原始源码；其1μs代理、源SHA和既有结果均未改，不能把旧成绩标成100版本。
- 后续实现时，另存候选并明确命名 `penalty_proxy_us`；只替换代表未知Miss额外代价的系数，不机械替换所有 `1.0`，不改归一化、读写带宽、概率先验、估值范围、预取预算或引擎真实罚值。纯算法双方案比较中的Miss项及AI代价项若同步调整，应一致记录；固定权重是否还需重训另作验证，不能默认为已完成。
