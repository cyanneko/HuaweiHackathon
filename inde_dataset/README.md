# inde_dataset 1.1.0

500 条训练数据、70 条测试数据，全部使用独立新种子生成，模拟数据量较大、分区倾斜和热点迁移下的 Hash Join 调度。每条输入都是完整工作负载，符合本仓库官方格式与数值限制，不复用原有数据。

## 场景分配

| 类别 | 分区概率机制 | 训练 | 测试 |
| --- | --- | ---: | ---: |
| 静态均匀随机 | 各分区等概率，作为对照 | 50 | 7 |
| 静态 Zipf 倾斜 | 随机分区排名，指数 1.05–1.95 | 50 | 7 |
| 静态对数正态倾斜 | 随机 lognormal 权重，σ=1.1–2.2 | 50 | 7 |
| 静态冷热混合 | 随机热点占约 4%–16% 分区，获得 78%–97% 请求质量 | 50 | 7 |
| 动态线性迁移 | 热点中心沿随机分区排名平滑移动、越界环绕 | 50 | 7 |
| 动态正弦迁移 | 随机幅度、周期与相位的往返迁移 | 50 | 7 |
| 动态周期跳变 | 等间隔、不同步长切换热点 | 50 | 7 |
| 动态不规则跳变 | 随机离散时间点切换到新热点 | 50 | 7 |
| 动态随机游走 | 热点随机移动或暂留，允许反向 | 50 | 7 |
| 动态渐变切换 | 三个热点簇通过 sigmoid 权重逐渐交接 | 50 | 7 |
| **合计** | 静态 40%，动态 60% | **500** | **70** |

每个窗口内的请求独立随机采样，不构造确定性的访问循环。静态案例在同一算子的整个 PROBE 阶段保持分区概率不变；动态案例按算子内部 PROBE 进度设置 64 个窗口。线性、正弦和 sigmoid 的连续函数在窗口中心离散求值，实际输入中没有连续时钟；跳变点也明确记录为窗口/算子内 PROBE 索引。

“热点份额”是混合分布的参数；高斯热点核在多个分区之间分配这一份额，并不表示某一个分区必有 78%–97% 请求。分区排名随机打乱，key 随机生成并保证 `key % P` 对应采样分区。

## 大数据量、倾斜与跨算子竞争

- 算子数 K=1–8，分区数 P=16/32/64，共享内存 256 MiB–4 GiB。
- 总构建数据为约 2–8 倍共享内存，模拟约 0.5–32 GiB 数据。输入文件只保存操作和 size 字段，不保存实际元组载荷。
- INSERT 采用 64 KiB–1 MiB 的大小批次，分区末尾可小于 64 KiB。它们是本调度模拟器的合法元组/批次，不代表生产库中的原始行宽。
- 原550例的 PROBE 数档位及比例保持不变；新增20例每条严格有2,000,000条总操作（包含INSERT、PROBE与SWITCH），其中PROBE数为总数扣除实际INSERT与SWITCH。
- 构建分区大小分别采用与初始热点一致、独立、反向以及近均匀四种配方，覆盖“大分区热”和“小分区热”。动态热点迁移后不再承诺原大小与热度关系不变。均匀请求本身没有冷热排名，相关配方不表示存在实际热相关性。
- 20% 使用先完成所有 BUILD 再 PROBE 的批处理顺序；80% 使用随机加权的异步算子流，允许一个算子 PROBE 时另一个还在 BUILD。K=1 的案例自然没有跨算子阶段重叠；实际重叠数见校验统计。
- 动态变化只作用于算子内部的分区请求概率；算子流的调度权重在单个案例内固定。不同阶段结束、算子退出仍会改变全局活动集合。
- BUILD 分区大小通过有上界的加权分配构造，最大不超过 0.7M，以保证整分区可载入。强倾斜可能被这一合法容量约束截断；PROBE 概率没有据算法表现做修剪。

## 划分、身份与适用边界

`train/` 恰好 500 条，`eval/` 恰好 70 条，测试版本见 `eval/VERSION`（1.1.0）。每个场景训练/测试的种子命名空间独立，使用相同已知生成机制；这是新种子的合成留出集，不是未知生产分布或官方隐藏测试。

原550例参数保持在 `recipe.json`，新增20例参数在生成前冻结到 `long_recipe.json`。不根据任何算法的成绩挑选、删样或改种子。所有数据只用于描述本包新场景，不替换 `final_dataset`、`dyna_dataset` 或 `balanced_dataset`，也不把换数据后的分数变化当成算法提升。

原始字节、去头部规范化操作流、以及 `key % P` 分区语义流均在本集内部和训练/测试之间去重；还与仓库已有 manifest 中可用的相同哈希比较。只对已有清单提供的哈希层级进行历史比较，不声称重算了所有历史压缩档案。

元数据包括未来概率参数和窗口，仅供离线生成、审核和训练划分管理；线上调度器仍只能使用官方回调公开状态，不得读取元数据或完整未来输入。

## 文件与复现

```text
inde_dataset/
  train/*.txt, *.meta.json      500 条输入与参数
  eval/*.txt, *.meta.json       70 条输入与参数，VERSION=1.1.0
  recipe.json                  生成前冻结的种子、参数和生成器指纹
  manifest.json                全部输入统计、元数据与输入/流指纹
  validation.json              独立合法性、规模、分布和隔离审核
  probe_windows.json           独立从真实输入统计的各算子/窗口分区计数
  reproducibility.json          20 条跨家族训练/测试样本重建核验
  tools/generate.py            Python 标准库生成器
  tools/verify.py              公共独立输入审计 + 流去重 + 窗口统计
  tools/reproduce.py           按冻结配方重建并比较字节与元数据
```

从仓库根目录执行：

```sh
python inde_dataset/tools/verify.py
python inde_dataset/tools/reproduce.py
# 原始550条重建验证（不覆盖原件）；新20条见后文
python inde_dataset/tools/reproduce.py --all
# 在新的目录重建原始550条；拒绝覆盖已有输入
python inde_dataset/tools/generate.py --out /path/to/new_inde_dataset
```

生成时的 Python 版本记录在 recipe 中。重建后以 SHA-256 核对，不假定所有解释器/数学库版本都产生完全相同字节。分布核验检查静态窗口参数不变、动态参数变化及实际峰值质量偏差，不能代替真实负载代表性或算法收益验证。

独立评测本包，使用已接入官方框架的 solver：

```sh
python evaluation/evaluate.py --datasets-root . --members inde_dataset --repeats 3 --out results/inde-v1.1.json --command ./build/solver "{input}"
```

按仓库当前 `case-mean-v1` 报告所有案例逐例均分，并保留完整 I/O、miss 和实际决策 CPU 耗时。单独选本包的分数仅代表这 70 条测试；不能与其他测试集直接混称同一成绩。


## 1.1.0 长样例补充

保留1.0.0的500条train和50条eval输入及元数据原字节，追加20条eval；10类场景各增加2条，静态新增8条、动态新增12条。所有新样例都严格N=2,000,000，合计40,000,000条操作，不把“200万总操作”写成“200万PROBE”。

每类各有K=4/P=32/M=512MiB/B=31和K=8/P=64/M=2GiB/B=1000两个配置；80%随机异步交错，20%全部BUILD后PROBE。构建大小与初始热度的四种关系各5条。

原始版本的manifest、validation、publication与README原字节归档在`versions/1.0.0/`。`long_prior_hashes.json`记录追加时对已有清单的去重依据；`long_probe_windows.json`保存新样例真实窗口统计。原550例以原审核加重新核对全部字节/元数据指纹继承，新20例完整重跑独立格式/阶段/容量/长度/窗口审核。

核验已发布副本和重建全部570条（临时输出，不覆盖原件）：

```sh
python inde_dataset/tools/verify.py
# 原550条的完整重建核验
python inde_dataset/tools/reproduce.py --all
# 新20条：默认抽2条，--all核验全部20条
python inde_dataset/tools/reproduce_long.py
python inde_dataset/tools/reproduce_long.py --all
```

`generate.py`保持1.0.0原生成器字节；`append_long.py`是新长例的追加入口，使用独立的`long_recipe.json`。完整新版本的身份与审核入口是当前`manifest.json`与`verify.py`。

长样例只按预先冻结的种子和参数生成，未按算法得分筛选。新旧样例及不同测量窗口的结果应分别展示，合并时每条eval等权，不按操作数加权。
