# final_dataset 2.0.0 · 随机大数据量与倾斜 Hash Join

500 条训练、50 条测试；每条是一个完整 Hash Join 调度工作负载。常规案例占 96%，特别 corner case 占 4%，训练和测试分别都低于 5%。测试目录为 `eval/`，与仓库公共评测工具兼容。

本版重点是一般随机情况下，构建数据超过共享内存、分区大小不均或访问频率倾斜时的 Hash Join。输入量、算子数、分区数、元组大小、内存压力、读写带宽和回调间隔随机变化。新生成的常规数据采用随机交错的 INSERT，以及给定概率分布下的独立随机 PROBE；不再将周期混叠、诱饵、精确容量、长重用距离或人工扫描循环作为常规主体。

## 数据组成

| 类型 | 训练 | 测试 |
| --- | ---: | ---: |
| 三方原训练集中的普通随机/倾斜案例 | 120 | 0 |
| 新生成：随机均匀 | 90 | 12 |
| 新生成：随机 Zipf 倾斜 | 108 | 14 |
| 新生成：随机热点/冷流混合 | 108 | 14 |
| 新生成：随机对数正态不均匀分布 | 54 | 8 |
| 特别 corner case | 20（4%） | 2（4%） |
| 合计 | 500 | 50 |

120 条复用数据来自 cyanneko 2 条、liunianwww 70 条、Vanius0525 48 条，固定于来源提交 `750618cead2d8f9d815a47fd8217fdab23d786dd`。只使用原 `train/`，不把旧评测数据改作训练。保留输入原字节和原元数据，详细路径与筛选规则见 `tools/source_selection_v2.json`。

筛选优先普通随机、自然热点、倾斜和算子竞争，排除容量边界、强制预取、人工周期等构造；另要求 B>1、带宽比<1000、总构建压力<=8、最大分区<0.9M。家族内优先较大的实际操作数，再按构建字节数和固定哈希排序，按分区语义流去重。三方适用数据量不同，因此不强行按成员均分。复用数据是一小部分历史补充，主规模由 380 条新训练和 50 条新测试提供。

新生成的数据综合三方的随机分布、分区大小倾斜、内存竞争和参数覆盖思想，统一使用可复现的新种子。普通随机分布中，“大数据量”与“数据倾斜”是正常工作负载，不算 corner case。

## 规模与随机分布

全部新常规案例至少包含 32,768 条真实操作，其中至少 12,000 条是 INSERT。整个训练集至少一半的案例操作数达到 65,536；48 条常规测试全部达到 65,536。训练和测试都保留超过 262,144 条操作的长案例。

| 已生成的实际规模 | 训练 | 测试 |
| --- | ---: | ---: |
| 总操作数 | 36,332,735 | 8,376,500 |
| 单例操作数中位数 | 67,628.5 | 156,456.5 |
| 单例最大操作数 | 487,220 | 465,295 |
| 至少 65,536 操作的案例数 | 260 | 48 |
| 至少 262,144 操作的案例数 | 8 | 8 |

输入文本合计 942,249,453 字节（约 942 MB）；全套共 44,709,235 条实际操作。少量复用案例较短，在清单中有明确来源，不将它们称为新生成的大记录数案例。

新数据的内存 M 为 64、128、256 或 512 MiB，累计构建数据约为 M 的 1.15–4 倍，因而覆盖大于内存的 Hash Join。每条 INSERT 都有随机生成的元组大小，构建字节数按输入中的 size 字段计量；文件存储操作和大小，不存储元组实际载荷。真实 INSERT/PROBE 条数、字节量、分区/访问倾斜统计见 `manifest.json` 和 `validation.json`。

四种新常规分布分别为：均匀随机请求、随机重排分区排名后的 Zipf 请求、随机选择热点集合后的冷热混合请求、随机对数正态概率请求。构建侧的分区大小和 Probe 热度分别生成，避免默认“大分区一定最热”。BUILD 操作全局随机交错，各算子恰好一次 SWITCH，然后执行随机 PROBE。少量复用数据保留普通 Markov 局部性和热点迁移，它们不宣称是静态独立同分布。

本包为合成场景配方，未使用真实生产流量或官方隐藏测试作为采样依据。

## Corner case 与隔离

特别案例仅有两类：活动分区对比 M 多一字节、明确访问空分区。训练各 10 条，测试各 1 条，总量分别为 4%。这些输入仍须符合官方数值和阶段约束。常规新数据的每个分区最多为 0.8M，没有特设恰好容量、周期访问或对抗式顺序。

训练与测试在原始字节、规范化操作流和 `key % P` 分区语义流三个层面均须无重复。全部 430 条新样例还与三方 1,625 条历史 train/eval，以及 1.0.0 的 550 条发布样例比较；复用旧训练是显式来源，不当作新生成数据。

所有新种子、参数和生成器身份先写入 `recipe.json` 再生成，不按算法成绩筛选、不失败换种子。本次只构造与审核数据，没有运行求解器或训练模型。公开后是固定测试集；如据此调参，应另留新测试。旧版 1.0.0 可从 Git 提交 `ee2ed4d5b10ac88b08d02a9d0fe10aefb09d38aa` 查看，本版升级 `eval/VERSION` 为 `2.0.0`。

## 使用与复现

```text
final_dataset/
  train/                         500 份输入及元数据
  eval/                          50 份测试及元数据，VERSION=2.0.0
  recipe.json                    冻结种子、430 个生成参数、120 条复用来源
  manifest.json                  全部 550 条的来源、哈希和实际统计
  validation.json                独立输入、规模、倾斜与隔离检查
  tools/build.py                 当前版本重建入口
  tools/build_v2.py              组装与冻结配方
  tools/random_workloads.py      随机大数据量/倾斜工作负载生成器
  tools/source_selection_v2.json  三方原训练来源与筛选证据
  tools/verify.py                独立审核入口
```

从仓库根目录运行，Python 3.10+，只用标准库：

```sh
python final_dataset/tools/verify.py
python final_dataset/tools/build.py
```

重建读取已发布配方，并核对已有文件，不改种子或参数。新版本应写入新输出目录，修改评测输入时必须升级版本与指纹。

单独评测这 50 条测试，替换为已接入官方兼容框架的 solver：

```sh
python evaluation/evaluate.py --datasets-root . --members final_dataset --repeats 3 --out results/final-v2.json --command ./build/solver "{input}"
```

本包位于仓库根部，避免被 `datasets/` 默认成员发现后与三方原集合重复计权。显式选集的成绩代表本包测试，不是三位成员旧测试的完整成绩。
